# 测试执行记录模板

## 0. 使用说明

- **定位**：`04-测试执行记录.md` 用于沉淀某个系统版本或某一轮回归执行的测试结果，支持把“测试结果”稳定回溯到需求点、测试点、自动化脚本和问题归因。
- **适用场景**：
  - 版本回归测试结束后需要形成正式记录
  - UI / API 自动化批量执行后需要沉淀结果
  - 里程碑评审、版本关闭前需要给出测试结论
- **上游输入**：
  - `Prds/` 模块目录下相关 `01-需求文档.md` / `01a-增量需求文档.md`（如有）
  - `03-测试用例文档.md`
  - 自动化执行报告、截图、日志、接口报告
  - `TRACE.yaml`
- **下游消费者**：版本评审、发布评审、`05-变更记录.md`、`TRACE.yaml` 状态更新、缺陷跟踪
- **产出原则**：
  1. 一份文档对应一个版本或一轮明确命名的执行批次。
  2. 不能只写“通过/失败”，必须至少回溯到 `REQ`、`FT/IT`、脚本/用例编号。
  3. 失败项必须给出失败分类、失败摘要和后续动作。
  4. 记录测试事实，不重写需求和设计正文。
- **输出路径**：输出到 `Prds/` 根目录下的系统级版本目录，例如 `Prds/V1.5.4.1/04-测试执行记录.md`。
