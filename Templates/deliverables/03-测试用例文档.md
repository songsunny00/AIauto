# 测试用例文档模板

## 0. 使用说明

- **上游输入**：
  - `docs/02-详细设计文档.md`（主要依据：功能级开发契约、呈现形式、路由、字段契约、权限、接口清单）
  - `docs/01-需求文档.md`（可选补充：功能清单、验收标准）
  - `docs/01b-数据流转设计.md`（可选补充：状态流、权限过滤、异常分支）
  - `docs/01c-原型文档.md`（可选补充：页面交互、空/错误状态）
  - `docs/02b-后台文档.md`（可选补充：接口完整定义、错误码、数据库约束）
  - `docs/02c-前端文档.md`（可选补充：前端验收清单、表单校验）
  - 参考示例：`framework/examples/OmicsDB-V1.0.0/04-详细设计文档.md`
- **下游消费者**：
  - 测试工程师（执行）
  - 开发工程师（自测）
  - 测试报告（按本文档的字段要求回填）
- **产出原则**：
  1. 用例必须覆盖：功能路径、接口路径、权限路径、异常路径四类。
  2. 用例编号规则统一，便于回归用例集筛选。
  3. 字段命名（接口字段、错误码、状态值）主要与 02 详细设计字段契约对齐；若 02b/02c 已生成，也必须保持一致，禁止改名。
  4. 关联需求编号默认引用 `docs/02-详细设计文档.md` 第 5 章需求实现单元中的编号；该编号必须与 `docs/01-需求文档.md` 中的功能点编号保持一致，不得在测试文档中自造编号。
  5. 本阶段不要求产出可执行测试脚本；用例描述需具体到能由人工或自动化复用。
  6. 示例片段仅作写法参考，禁止把示例的业务事实复制为新项目正文。
- **命名约定**：输出到 `docs/03-测试用例文档.md`。

## 4. 接口用例

> **填写指引**：按接口组织。**用例字段固定**：用例编号 / 关联需求编号 / 接口 / 方法 / 请求参数 / 正常返回 / 异常返回 / 边界值 / 权限场景。关联需求编号应优先绑定到支撑该接口的 `docs/02-详细设计文档.md` 第 5 章需求实现单元编号，并与 `docs/01-需求文档.md` 中的功能点编号保持同号；接口用例可以多个用例关联同一个需求编号。若 `docs/02b-后台文档.md` 已生成，请求参数、正常返回、异常返回、边界值应以 02b 为准；若 02b 未生成，则以 02 第 6 章接口清单与第 5 章字段契约为基础编写，并将待 02b 回填的参数/错误码/边界条件显式标注。建议编号 `IT-{模块编码}-{页面编码}-{接口序号}-{用例序号}`（IT = Interface Test）。
>
> **字段清单**（接口用例必备字段）：
>
> | 字段名 | 类型 | 必填 | 说明 | 示例值 |
> |---|---|---|---|---|
> | 用例编号 | String | 是 | `IT-{模块}-{页面}-{接口}-{序号}` | `IT-INSIGHT-LIST-01-001` |
> | 关联需求编号 | String | 是 | 来源于需求功能点编号 | `REQ-INSIGHT-LIST-001` |
> | 接口 | String | 是 | 路径 | `/api/v1/oa-orders` |
> | 方法 | Enum | 是 | GET/POST/PUT/DELETE | `GET` |
> | 请求参数 | JSON/Query | 是 | 真实可用 | `?page=1&pageSize=10` |
> | 正常返回 | JSON/断言 | 是 | code=0 + 字段断言 | 见示例 |
> | 异常返回 | Table | 是 | 错误码 → 触发条件 | `PARAM_001` |
> | 边界值 | Array | 是 | 上下界、空、超长 | `pageSize=0 / 101 / 负数` |
> | 权限场景 | Table | 是 | 角色 → 期望（200/403/数据范围） | 见示例 |
>
> **示例片段**（摘自示例 6.1 通用响应与 6.2.1 登录接口错误码）：
>
> ```json
> { "code": "0", "data": { "accessToken": "{jwt}" } }
> ```
>
> | 错误码 | 说明 |
> |---|---|
> | `AUTH_001` | 用户名或密码错误 |
>
> **常见错误**：
> - 接口用例只测 200，缺边界值与权限矩阵。
> - 用例没有断言响应字段，只看 HTTP 状态。
> - 权限场景只测能访问的角色，未测应被拒绝的角色。

## 5. 权限用例

> **填写指引**：按「角色 × 模块/接口」二维矩阵展开。每行一个用例：角色 + 操作 + 期望（允许/拒绝/数据范围）。覆盖详设第 5 章的数据权限规则。
>
> **字段清单**：
>
> | 字段名 | 类型 | 必填 | 说明 | 示例值 |
> |---|---|---|---|---|
> | 用例编号 | String | 是 | `PT-{模块}-{页面}-{序号}` | `PT-INSIGHT-LIST-001` |
> | 角色 | Enum | 是 | 角色编码 | `CUSTOMER` |
> | 操作 | String | 是 | 接口或前端动作 | 访问 `/system/users` |
> | 期望 | String | 是 | 允许/拒绝/数据范围 | 拒绝（HTTP 403） |
>
> **示例片段**（摘自示例 5.2.2 数据权限规则）：
>
> | 角色 | 查询条件 |
> |---|---|
> | SALES | 自己提交的 + 所管客户提交的 OA 单 |
> | CUSTOMER | 仅本机构的 OA 单 |
>
> **常见错误**：
> - 只覆盖 ADMIN，未测 SALES/CUSTOMER 的数据范围。
> - 只测拒绝（403），未测“允许但只能看到部分数据”。

| 用例编号 | 角色 | 操作 | 期望 |
|---|---|---|---|
| PT-INSIGHT-LIST-001 | `CUSTOMER` | `GET /api/v1/oa-orders` | 200；`data.list` 全部 `applicantId` 属于本机构用户 |
| PT-INSIGHT-LIST-002 | `SALES` | `GET /api/v1/oa-orders` | 200；`data.list` 全部 `applicantId ∈ [自己ID, 所管 CUSTOMER ID 列表]` |
| PT-SYSTEM-USER-001 | `SALES` | `POST /api/v1/system/users`（创建 SALES） | 403（SALES 只能创建 CUSTOMER） |

## 6. 异常用例

> **填写指引**：覆盖网络异常、超时、Token 过期/失效、参数校验失败、并发冲突、外部依赖失败、补偿回滚（取自数据流转设计的异常分支）。

> | 异常类型 | String | 是 | | Token 过期 |
> | 触发方式 | String | 是 | 操作步骤 | 用过期 Token 调用接口 |
> | 期望表现 | String | 是 | 接口/前端 | 401 + `AUTH_004`；前端清 Token 跳登录 |

> **示例片段**（摘自示例 11.2 业务错误码）：
>
> | 错误码 | 说明 |
> |---|---|

> | `AUTH_005` | Token 已失效（在黑名单中） |
>
> **常见错误**：
> - 异常用例只覆盖业务错误码，未覆盖网络层（超时、断网、502）。
