# 前端文档模板（可选）

## 0. 使用说明

- **上游输入**：
  - `docs/02-详细设计文档.md`（必读，功能级开发契约：呈现形式、路由、字段契约、权限、接口清单）
  - `docs/01-需求文档.md`（可选回看，业务目标和角色）
  - `docs/01b-数据流转设计.md`（可选回看，数据来源、状态流、权限过滤、异常分支）
  - `docs/01c-原型文档.md`（可选回看，页面、控件、字段、交互、空状态/错误状态）
  - `docs/02b-后台文档.md`（可选，若已生成，则用于接口完整定义、错误码、响应结构）
  - 参考示例：`framework/examples/OmicsDB-V1.0.0/04-详细设计文档.md`（确认字段命名）
- **下游消费者**：
  - 前端开发工程师（直接对照实现页面）
  - 测试工程师（功能用例补充交互细节、异常用例补充提示文案）
- **产出原则**：
  1. 前端文档不允许“按页面静态实现”，必须基于数据流转把状态、权限、异常路径写清楚。
  2. 页面呈现形式、路由、字段契约必须与 `docs/02-详细设计文档.md` 第 5 章一致；如果 `docs/02b-后台文档.md` 已生成，接口路径、请求参数、响应字段、错误码必须与 02b 完全一致；如果 02b 未生成，则以 02 第 6 章接口清单和第 5 章字段契约为准，后续生成 02b 时再回填细节。
  3. `docs/02-详细设计文档.md` 第 5 章中的 `REQ-...` 需求编号是 02c 的追踪主键；页面结构、API 调用关系、关键实现说明必须显式沿用对应需求编号进行追踪。
  4. 角色编码大写英文（`ADMIN`/`DELIVERY`/`SALES`/`CUSTOMER`），权限编码 `module:action`。
  5. 示例片段仅作写法参考，禁止把示例的业务事实复制为新项目正文。
- **命名约定**：输出到 `docs/02c-前端文档.md`。

## 2. 路由结构

> **填写指引**：列出全部一级/二级路由以及由 02 详细设计标记为“新增页面”的路由。每条独立页面路由必须包含 path、routeName、组件路径、父级菜单、面包屑、权限、是否菜单展示、返回路径。弹窗/抽屉/详情区不是独立路由，需在「页面结构」章节说明其触发页面、打开方式、关闭/刷新行为。
>
> **字段清单**：
>
> | 字段名 | 类型 | 必填 | 说明 | 示例值 |
> |---|---|---|---|---|
> | 路由路径 | String | 是 | route path | `/system/users/create` |
> | routeName | String | 是 | 路由唯一名 | `SystemUserCreate` |
> | 组件 | String | 是 | 相对 `src/` | `src/views/system/users/Create.vue` |

> | 面包屑 | String | 条件必填 | 新增页面必填 | `系统管理 / 用户管理 / 新增用户` |
> | 权限编码 | String | 是 | `module:action` 或 `已登录` 或 `公开` | `system:user:add` |

## 6. API 调用关系

> **填写指引**：**本节是前端字段一致性的关键节点**。调用位置、呈现形式、路由必须与 `docs/02-详细设计文档.md` 第 5 章功能级开发契约一致；如果 `docs/02b-后台文档.md` 已生成，接口路径、请求参数、响应字段、错误码必须与 02b 完全一致；如果 02b 未生成，则以 `docs/02-详细设计文档.md` 第 6 章接口清单和第 5 章字段契约为准，并显式标注待 02b 回填的接口细节。每个接口给出：关联需求编号、调用位置（页面/弹窗/抽屉/组件/store）、请求字段、响应字段使用、错误处理。
>
> **字段清单**：
>
> | 字段名 | 类型 | 必填 | 说明 | 示例值 |
> |---|---|---|---|---|
> | 关联需求编号 | String/Array<String> | 是 | 对应 02 第 5 章需求实现单元 | `REQ-INSIGHT-LIST-001` |
> | 接口 | String | 是 | METHOD + path | `GET /api/v1/oa-orders` |
> | 封装函数 | String | 是 | `src/api/` 下函数名 | `fetchOAOrderList` |
> | 调用方 | String | 是 | 页面/组件/store | `/insights` 页面 |
> | 请求字段 | Array | 是 | camelCase，与详设一致 | `page, pageSize, oaNo` |
> | 响应字段使用 | Array | 是 | 哪些字段被绑定到 UI | `list[].oaNo, list[].status` |
> | 错误处理 | String | 是 | 错误码 → 文案 | `AUTH_004 → 跳登录` |
>
> **示例片段**（摘自示例 6.1 统一响应结构）：
>
> ```json
> { "code": "0", "message": "success", "traceId": "abc123", "data": {} }
> ```
>
> **常见错误**：
> - 前端用 `oa_no`、后端响应是 `oaNo`，导致取值 undefined。
> - 错误码处理散落在各组件，未统一拦截。
> - 401 后没有清 Token 直接跳登录，下次进入仍带旧 Token。
> - API 调用关系没有需求编号，无法与 02 第 5 章建立稳定映射。

| 关联需求编号 | 接口 | 封装函数 | 调用方 | 请求字段 | 响应字段使用 | 错误处理 |
|---|---|---|---|---|---|---|
| `REQ-AUTH-LOGIN-001` | `POST /api/v1/auth/login` | `loginApi` | `Login.vue` | `username, password` | `accessToken → userStore.token` | `AUTH_001 → 提示错误` |
| `REQ-INSIGHT-LIST-001` | `GET /api/v1/oa-orders` | `fetchOAOrderList` | `Insights/Index.vue` | `page, pageSize, oaNo` | `list[].oaNo, list[].status, total` | 401 → 跳登录 |

## 10. 异常处理

> **填写指引**：列出所有可能的异常类型（网络异常、超时、401、403、404、500、业务错误码），给出统一拦截位置（Axios 响应拦截器）、UI 表现、是否上报。
