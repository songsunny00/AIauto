# 变更记录模板

## 0. 使用说明

- **定位**：`05-变更记录.md` 用于沉淀系统级版本的正式变更说明，面向里程碑评审、对外发布说明或项目内部版本公告。
- **适用场景**：
  - 版本发布前需要形成正式变更说明
  - 里程碑交付时需要汇总本版变化范围
  - 需求交接开发后又出现增量需求、范围调整、验收变化或正式回写动作时，需要保留版本级留痕
- **上游输入**：
  - `Prds/Vx.y.z/01-需求文档.md`（如有）
  - 相关模块 `01-需求文档.md`
  - `CHANGELOG.md`
  - 后续 `04-测试执行记录.md`（如有）
- **下游消费者**：项目组、业务方、发布评审、运维/实施、后续版本回溯
- **产出原则**：
  1. 只记录本版本已确认的正式变化，不写未定项。
  2. 重点说明“改了什么、影响什么、是否需要关注”，不重写需求和设计细节。
  3. 每条变更尽量能回溯到模块或 `REQ` 编号。
  4. 若项目不单独维护其他追踪文件，可由 `01 / 04 / 05 / CHANGELOG` 共同承担版本追溯。
- **输出路径**：输出到 `Prds/` 根目录下的系统级版本目录，例如 `Prds/V1.5.4.1/05-变更记录.md`。

填写要求：

- “变更类型”优先使用：新增 / 修改 / 删除 / 优化 / 修复。
- 若某项变化只影响实现、不影响用户感知，可在“用户可见影响”中明确写“无”。
- 若脚本、测试点、执行口径需要跟着变化，必须显式标注。
- 同一版本若发生多次变更，按实际变更日期逐行追加，不要覆盖旧记录。
