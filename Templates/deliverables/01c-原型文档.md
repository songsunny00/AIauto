# 原型说明文档模板（可选）

## 0. 使用说明

- **定位**：`01c-原型文档.md` 是**可选的原型说明文档**。当某个功能点已经有专门的 HTML 原型、设计稿或可交互原型页面时，用本文档把“原型路由 / 页面”和“需求模块 / 功能点 / 前端实现要求”对齐清楚。
- **什么时候产出**：
  - 已有独立原型页面，需要把原型和需求编号对齐
  - 页面交互较复杂，需要单独说明前端实现要求
  - 页面风格、展示规则、状态表现需要提前统一
- **什么时候可以不产出**：
  - 没有独立原型资源
  - 页面交互简单，`01` 和 `02` 已足够表达
- **上游输入**：
  - `docs/01-需求文档.md`
  - 对应版本目录下的 `01-需求文档.md`（如本次按版本组织）
  - 产品提供的 HTML 原型、设计稿、Figma / Axure / 静态页面地址（如有）
- **下游消费者**：产品评审、前端实现、测试设计、`02-详细设计文档.md`、`02c-前端文档.md`、`03-测试用例文档.md`
- **产出原则**：
  1. 重点写清楚：**原型路由对应哪个需求模块、页面怎么交互、前端有哪些实现约束、页面风格怎么统一**。
  2. 不写 HTML 生成工艺，不写后端实现，不写数据库设计。
  3. 页面名、按钮名、字段名、状态名要和 `01/02/03` 保持一致，不能在原型文档里另起一套叫法。
- **命名约定**：输出到 `docs/01c-原型文档.md`；页面编码使用 `P{两位}`（如 `P01`）；原型路由优先使用前端约定的 kebab-case。

|---|---|---|---|---|---|---|
| `P01` | {页面名} | `/{route}` | {模块} | `REQ-{MODULE}-{PAGE}-001` | {页面用途} | {说明} |
| `P02` | {弹窗/抽屉名} | `{由哪个页面触发}` | {模块} | `REQ-{MODULE}-{PAGE}-{SUBPAGE}-001` | {用途} | {说明} |

填写要求：

- 一个原型页面可以对应多个 `REQ`，但必须显式列出。
- 同一路由下的列表页、弹窗、抽屉、Tab，建议拆开写。
- 不能只写页面名，不写需求编号。

## 6. 评审结论与回写要求

> **填写指引**：原型评审如果形成了稳定结论，必须说明回写到哪里。

| 评审结论 | 影响文档 | 回写动作 | 责任角色 |
|---|---|---|---|
| {结论} | `01 / 02 / 02c / 03` | {新增 / 修改 / 同步} | {产品 / 前端 / 测试} |

回写原则：

- 原型评审影响需求口径 → 回写 `01`
- 原型评审影响页面结构 / 交互规则 → 回写 `02` 或 `02c`
- 原型评审影响测试路径 / 状态展示 → 回写 `03`
