# Templates — 需求开发测试一体化模板中心

## 1. 目标

`Templates/` 用于沉淀“需求 → 设计 → 开发 → 测试”一体化协同过程中的标准模板、追踪治理模板和原型脚手架。

本目录面向两个目标：

1. **流程治理**：让需求、详细设计、测试用例等正式交付物有统一编号和稳定结构。
2. **平台复用**：让 AI / skill / agent 在固定模板之上稳定生成文档、测试骨架和追踪资产。

## 3. 编号规则

### 3.1 正式交付物

- `00-全局公共说明.md`：项目级公共基线
- `01-需求文档.md`：全量需求基线
- `01b-数据流转设计.md`：可选，复杂数据流 / 状态机 / 权限过滤时使用
- `01c-原型文档.md`：可选，页面 / 交互 / 原型评审时使用
- `02-详细设计文档.md`：开发前主设计文档
- `02b-后台文档.md`：可选，后端实现细化文档
- `02c-前端文档.md`：可选，前端实现细化文档
- `03-测试用例文档.md`：测试设计文档
- `04-测试报告文档.md`：测试报告模板，汇总某个版本或测试轮次的范围、统计、结论和发布建议
- `04b-测试执行记录.md`：测试执行明细，记录测试点、脚本、结果、失败归因、证据和回归状态
- `05-变更记录.md`：系统级版本正式变更说明
- `INDEX.md`：模块叶子目录索引模板

### 3.2 编号原则

- `01` 系列都属于需求侧基线与补充材料。
- `01b / 01c` 是条件触发型可选文档，不是所有需求都强制产出。
- 进入开发实施阶段后，编号从 `02` 收敛。
- `04 / 04b / 05` 是系统级版本文档，放在 `Prds/` 根目录下的版本目录中使用。
- `04b` 先沉淀逐项执行事实与证据，`04` 再基于执行记录形成面向评审和发布决策的测试报告。
- **正式交付物进入编号体系；生成工艺和实施说明不进入编号体系。**

## 4. 推荐文档链路

### 4.1 全新或复杂需求

```text
00 → 01 → 01b（按需）→ 01c（按需）→ 02 → 02b/02c（按需）→ 03
```

### 4.2 版本需求

```text
00 → 01 → 01a（按需）→ 01b/01c（按需）→ 02 → 02b/02c（按需）→ 03
                                                               ↓
                                                     测试执行与证据采集
                                                               ↓
                                             04b-测试执行记录.md → 04-测试报告文档.md
                                                               ↓
                                             05-变更记录.md（有版本变更时）
                                                               ↓
                                                     Prds/CHANGELOG.md
```

### 4.3 文档链路图

```text
┌────────────────────┐
│ 00-全局公共说明    │
│ 项目级公共基线     │
└─────────┬──────────┘
          ↓
┌────────────────────┐
│ 01-需求文档        │
│ 需求范围 / REQ / 验收标准 │
└──────┬─────┬───────┘
       │     ├── 按需 → 01a-增量需求文档
       │     ├── 按需 → 01b-数据流转设计
       │     └── 按需 → 01c-原型文档
       ↓
┌────────────────────┐
│ 02-详细设计文档    │
│ 页面 / 接口 / 字段 / 权限 │
└──────┬─────┬───────┘
       │     ├── 按需 → 02b-后台文档
       │     └── 按需 → 02c-前端文档
       ↓
┌────────────────────┐
│ 03-测试用例文档    │
│ FT / IT / PT / ET  │
└─────────┬──────────┘
          ↓
┌────────────────────┐
│ 测试执行            │
│ 手工 / UI / API     │
└─────────┬──────────┘
          ↓
┌────────────────────┐
│ 04b-测试执行记录   │
│ 逐项结果 / 证据 / 失败归因 │
└─────────┬──────────┘
          ↓
┌────────────────────┐
│ 04-测试报告文档    │
│ 统计 / 结论 / 发布建议 │
└─────────┬──────────┘
          ↓
┌────────────────────┐
│ 05-变更记录        │
│ 仅在需求、范围或验收变化时 │
└─────────┬──────────┘
          ↓
┌────────────────────┐
│ Prds/CHANGELOG.md  │
│ 系统级变更总览     │
└────────────────────┘
```

链路使用规则：

- `01` 定义唯一稳定的需求基线和 `REQ` 编号，下游文档不得重新创建需求编号。
- `02` 将需求点转换为页面、接口、字段、权限和实现约束；`02b/02c` 只按需补充。
- `03` 将需求和设计转换为可执行测试点，`ET` 直接挂在对应功能点或接口点下。
- `04b` 记录逐项测试事实，是 `04` 测试报告的明细依据；失败项必须保留分类、证据和后续动作。
- `04` 面向版本评审和发布决策，汇总执行范围、统计指标、缺陷风险和测试结论，不替代 `04b` 的逐项记录。
- `05` 只在需求交接后发生增量、范围调整、验收变化或正式回写时启用。
- `Prds/CHANGELOG.md` 维护系统级持续变更总览，版本关闭时同步更新。

### 5.1 `deliverables/`

放正式模板。所有会进入项目产物编号体系的文档，都在这里维护。

### 5.2 `governance/`

放需求到代码映射和其他治理辅助模板。当前主要保留 `prd-to-code.yaml`；需求、测试执行和版本变更的状态分别回写到 `01`、`03`、`04b`、`04`、`05` 与 `Prds/CHANGELOG.md`，不再依赖单独的追踪文件。

### 5.3 `prototypes/`

放原型脚手架资源，如 HTML 静态原型基础目录、可复用样例等。该目录服务于产品原型搭建，不属于正式交付物模板。

### 5.4 单实例入口文档与可复用模板的区别

以下资产虽然与模板体系强相关，但更适合作为仓库中的单实例入口文档直接维护，而不是放进 `Templates/` 里重复复用：

- 仓库根 `README.md`
- `Prds/README.md`
- `Prds/CHANGELOG.md`
- `skills/README.md`
- `Agents/AGENTS.md`

建议原则：

- 会在多个模块/目录重复创建的，优先放进 `Templates/`
- 只会在仓库中存在一份、承担导航或总览职责的，直接在实际路径维护

## 6. 产出文件命名建议

项目落地时，推荐以 `Prds/` 作为需求、设计、测试和版本资产根目录；业务模块目录保留模块入口，具体版本交付物统一放在浅层版本目录中。例如：

```text
Prds/
├─ README.md
├─ CHANGELOG.md
├─ 系统变更说明.md
├─ CONFIG-配置中心/
│  └─ README.md
└─ V1.6.1/
   ├─ assets/
   ├─ 01-需求文档.md
   ├─ 01a-增量需求文档.md       # 按需启用
   ├─ 02-详细设计文档.md
   ├─ 02b-后台文档.md            # 按需启用
   ├─ 02c-前端文档.md            # 按需启用
   ├─ 03-测试用例文档.md
   ├─ 04b-测试执行记录.md
   ├─ 04-测试报告文档.md
   └─ 05-变更记录.md             # 按需启用
```

说明：

- `Prds/` 表示单个系统项目的需求资产根目录，业务模块目录用于模块导航和归属说明。
- 版本目录不再继续嵌套到模块叶子目录，`01/01a/02/03/04b/04/05` 等版本资产在同一版本目录内维护。
- `01-需求文档.md` 是版本正式需求基线；`01a-增量需求文档.md` 只在该版本存在新增或调整需求时启用。
- `04b-测试执行记录.md` 记录逐项执行结果、失败归因和证据；`04-测试报告文档.md` 汇总测试统计、风险、结论和发布建议。
- `05-变更记录.md` 只记录需求交接后的增量、范围调整、验收变化或正式回写。
- `Codes/mappings/prd-to-code.yaml` 维护需求到代码的映射；测试脚本和报告位于 `Tests/`，当前 UI 自动化入口为 `Tests/ui-automation/`。
- `Prds/CHANGELOG.md` 作为系统级持续变更总览，版本关闭时同步更新。

## 7. 使用原则

- 正文优先用中文业务表达，代码标识 / 接口字段 / 角色编码 / 权限编码保留英文。
- 功能点编号由需求文档统一定义，下游文档必须沿用，不得自造编号。
- 版本需求默认直接维护在版本目录下的 `01-需求文档.md`，避免并行维护额外需求正文。
- 所有模板都应服务于“路径主线 + 功能点编号主线”的双轨追踪。
- 原型脚手架资源不能替代正式交付物说明文档。
