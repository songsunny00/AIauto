## 1. 背景与目标

本设计用于在 `d:\AIauto` 中建立一套面向前后端业务系统的文档模板体系，帮助 AI 稳定产出从需求到开发、测试所需的高质量文档。

目标不是先做自动化平台，而是先沉淀可复用的模板与 Prompt，使 Claude Code、Cursor 等 AI 编码工具能够按统一文档链路生成类似 `V1.0.0_详细说明书.md` 的完整交付文档。

适用项目类型：管理后台、门户系统、CRUD 系统、权限系统、流程型业务系统等前后端分离业务系统。

## 2. 范围

### 2.1 本阶段包含

- 建立 `framework/` 标准目录。
- 编写 8 份模板文件：6 份 Markdown 文档模板 + 1 份 HTML 原型生成说明模板 + 1 份派生 API 接口文档模板。
- 编写 8 份对应的 AI 生成 Prompt。
- 额外编写 1 份 OpenAPI 规范生成说明模板 + 1 份对应 Prompt（可选输出，按需触发）。
- 将 OmicsDB V1.0.0 现有文档归档为示例。
- 明确文档之间的依赖关系、字段映射、一致性检查规则、迁移规则和框架文件验收标准。

### 2.2 本阶段不包含

- 不开发命令行脚手架。
- 不实现一键生成全链路文档的平台。
- 不直接生成业务代码。
- 不产出可执行自动化测试脚本。

### 2.3 HTML 原型的边界

HTML 原型属于设计评审交付物，不属于业务代码。允许 AI 根据 Markdown 原型文档和 HTML 原型 Prompt 生成静态 `.html` 文件，用于浏览器预览页面布局和交互状态。

HTML 原型约束：

- 输出目录：`docs/prototypes/html/`。
- 每个页面一个 `.html` 文件，入口文件为 `index.html`。
- 只使用静态数据，不连接后端接口。
- 只模拟页面跳转、弹窗、抽屉、筛选、空状态、错误状态等评审所需交互。
- 可复用 `product-design-system-main/product-design-system-main/product-context/组件模板/` 中的 HTML 组件模板。
- 不作为前端生产代码，不进入 `src/`。

### 2.4 接口规范的输出策略

接口规范的唯一事实源是「详细设计文档」的接口章节。下游可派生两种产物：

- **派生 Markdown API 接口文档**（默认输出）：`docs/04a-API接口文档.md`，从详细设计接口章节抽取，供前后端联调、外部团队对接、接口走查时单独阅读。
- **可选 OpenAPI 规范**（按需输出）：`docs/api/openapi.yaml`，用于 Mock Server、前端代码生成、自动化接口测试、Postman 导入等场景。

两份派生产物都不允许独立修改接口定义；当与详细设计冲突时，以详细设计为准并重新生成派生产物。

## 3. 文档链路

最终文档链路如下：

```text
   需求文档 ──┐
数据流转设计 ─┼─► 详细设计文档 ─┬─► 派生：API 接口文档（Markdown）
   原型文档 ─┘                  ├─► 派生：OpenAPI 规范（可选）
      │                          ├─► 前端文档 ──┐
      │                          └─► 测试用例文档 ┴─► 开发 → 测试报告
      │
      └─► HTML 静态原型（评审用，不作为开发输入的唯一依据）
```

### 3.1 上游文档

#### 需求文档

说明项目背景、目标、角色、业务流程、功能模块、全局规则、非功能需求，是所有下游文档的业务来源。

#### 数据流转设计

描述系统内外部数据如何流转，包括核心实体、状态流、数据来源、数据去向、异常分支、权限过滤规则。

#### 原型文档

采用文字版规格 + HTML 静态原型：

- Markdown 原型文档用于描述页面结构、控件、字段、交互、跳转、状态展示，是详细设计和前端文档的正式输入。
- HTML 静态原型用于人工评审页面布局与交互，可复用现有 `product-design-system-main` 中的组件模板。

### 3.2 枢纽文档

#### 详细设计文档

详细设计文档作为开发前最终对齐稿，吸收原后端文档职责，包含：

- 系统概述
- 技术架构
- 功能结构
- 模块详细设计
- 接口设计
- 数据库设计
- 安全设计
- 缓存设计
- 日志设计
- 错误码定义

它是后续前端文档、测试用例文档、开发工作的主要依据。

### 3.3 下游文档

#### 前端文档

面向前端开发，描述页面路由、组件结构、状态管理、接口调用、权限控制、表单/表格配置、交互细节、异常提示和验收点。

前端文档读取需求、数据流转、原型和详细设计。数据流转用于确认页面数据来源、状态流、权限过滤和异常分支，避免前端只按页面静态展示实现。

#### 测试用例文档

包含两类测试：

- 功能用例：按模块编写用例编号、前置条件、步骤、预期结果、优先级。
- 接口用例：按接口编写请求参数、正常返回、异常返回、边界值、权限场景。

测试用例文档读取需求、数据流转、原型、详细设计和前端文档。数据流转用于补充状态流、权限和异常路径测试。

本阶段不要求同步生成可执行测试脚本。

## 5. 命名与术语规范

### 5.1 文档语言

- 文档正文、章节标题、说明文字使用中文。
- 代码标识、接口字段、数据库字段、枚举编码使用英文。
- 中文业务状态可以在界面展示中使用，但要在详细设计中定义对应编码或存储值。

### 5.2 文件命名

框架模板文件命名：`{两位阶段编号}-{文档名}.md`。

新项目生成文档命名：`docs/{两位阶段编号}-{文档名}.md`。

Prompt 中的任务段和输出段必须统一使用该命名方式。例如：

```text
输出到 docs/04-详细设计文档.md
```

### 5.3 API 与字段命名

- API 前缀默认使用 `/api/v1`，除非需求明确指定其他版本。
- REST 路径使用 kebab-case 或资源复数形式，例如 `/api/v1/oa-orders`。
- JSON 字段使用 camelCase，例如 `oaNo`、`taskNo`、`applyTime`。
- 数据库字段使用 snake_case，例如 `oa_no`、`task_no`、`apply_time`。
- 前端变量和函数使用 camelCase。

### 5.4 角色与状态命名

- 角色编码使用大写英文，例如 `ADMIN`、`DELIVERY`、`SALES`、`CUSTOMER`。
- 权限编码使用小写命名空间格式，例如 `menu:insights`、`tasks:view`。
- 状态必须在需求或详细设计中统一定义：展示值、存储值、接口值不得各自发散。

## 6. 模板设计规范

采用“重模板 + 轻 Prompt”的方式。模板是单一事实源，Prompt 只负责编排和调用。

每份模板使用统一骨架：

```markdown
# {文档名}模板

## 0. 使用说明
- 上游输入：...
- 下游消费者：...
- 产出原则：...
- 命名约定：...

## 1. {章节名}
> **填写指引**：...
> **字段清单**：...
> **示例片段**：...
> **常见错误**：...

正文模板内容。

## 2. {章节名}
...

## 附录 A. 与下游文档的字段映射
...

## 附录 B. 一致性检查清单
- [ ] ...
```

### 6.1 每节必须包含的四件套

#### 填写指引

说明本节要回答的问题、必填项、可选项、约束和输出深度。

#### 字段清单

用表格列出字段名、类型、是否必填、说明、示例值。字段命名要贯穿需求、详设、接口、前端和测试文档。

#### 示例片段

从 `framework/examples/OmicsDB-V1.0.0/` 摘取一小段同类内容作为参考。示例只用于说明写法，不应被原样复制到新项目。

#### 常见错误

列出 AI 容易犯的错误，例如：

- 角色编码大小写不一致。
- 接口响应结构不一致。
- 状态值在不同文档里中英文混用。
- 数据实体字段在需求和接口里命名不同。
- 将详细设计写成纯需求说明，缺少接口和数据库落地细节。

### 6.2 每份模板的最低内容要求

每份模板至少必须包含：

- `## 0. 使用说明`
- 正文章节
- 每个正文章节的填写指引
- 每个涉及结构化数据章节的字段清单
- 至少 1 个示例片段
- 至少 1 组常见错误
- `## 附录 A. 与下游文档的字段映射`
- `## 附录 B. 一致性检查清单`

### 6.3 附录 A：字段映射

每份文档要声明关键字段如何流向下游。例如：

```text
需求文档：OA单号 → 详细设计：oaNo → 接口响应：oaNo → 前端表格列：oaNo → 测试断言：oaNo
```

字段映射用于保证文档链路一致性。

### 6.4 附录 B：一致性检查清单

每份模板结尾都提供 AI 自检清单。AI 生成文档后必须逐项检查并修正不一致项。

## 7. Prompt 设计规范

Prompt 采用轻量结构，每份 Prompt 固定 5 段：

```markdown
# {文档名} 生成 Prompt

## 角色
你是一名熟悉前后端业务系统的 {岗位}。

## 输入
- 必读：framework/templates/{对应模板}.md
- 上游文档：...
- 参考示例：framework/examples/OmicsDB-V1.0.0/{对应文档}.md

## 任务
按模板章节顺序逐节填写，输出到 docs/{两位阶段编号}-{文档名}.md。

## 约束
- 严格遵循模板每节“填写指引”。
- 字段命名必须与上游文档一致。
- 完成后执行模板附录 B 自检清单。

## 输出
单个 Markdown 文件，路径 docs/{两位阶段编号}-{文档名}.md。
```

### 7.1 各 Prompt 的上游依赖

| Prompt | 必读上游 |
|---|---|
| 01-需求文档.prompt.md | 用户原始需求、业务背景、访谈记录 |
| 02-数据流转设计.prompt.md | 需求文档 |
| 03-原型文档.prompt.md | 需求文档、数据流转设计 |
| 03-原型-HTML.prompt.md | 原型文档、HTML 组件模板 |
| 04-详细设计文档.prompt.md | 需求文档、数据流转设计、原型文档 |
| 04a-API接口文档.prompt.md | 详细设计文档（接口章节为唯一事实源） |
| 05-前端文档.prompt.md | 需求文档、数据流转设计、原型文档、详细设计文档 |
| 06-测试用例文档.prompt.md | 需求文档、数据流转设计、原型文档、详细设计文档、前端文档 |
| 07-OpenAPI规范.prompt.md | 详细设计文档（接口章节为唯一事实源） |

### 7.2 每份 Prompt 的最低内容要求

每份 Prompt 至少必须：

- 指向唯一对应模板。
- 列出必读上游文档。
- 说明输出路径。
- 要求遵循模板填写指引。
- 要求执行模板自检清单。
- 要求不要复制示例事实到新项目。

## 8. 各模板内容边界

### 8.1 需求文档模板

必须包含：

- 项目概述
- 项目目标
- 角色与权限
- 主业务流程
- 功能清单
- 模块详细需求
- 全局规则
- 非功能需求
- 外部系统依赖
- 验收标准

不应包含：

- 具体数据库表结构
- 具体接口路径
- 前端组件实现细节

### 8.2 数据流转设计模板

必须包含：

- 外部系统关系
- 核心数据实体
- 实体关系
- 主流程数据流
- 状态流转
- 权限过滤规则
- 异常流和补偿策略
- 数据一致性要求

不应包含：

- 页面布局细节
- 完整接口定义

### 8.3 原型文档模板

必须包含：

- 页面清单
- 路由建议
- 页面布局
- 表格列定义
- 表单字段定义
- 弹窗/抽屉/详情区定义
- 操作按钮与交互状态
- 错误提示和空状态
- HTML 原型生成要求

不应包含：

- 后端 Service 实现
- 数据库建表 SQL

### 8.4 原型 HTML 说明模板

这是 HTML 原型生成说明模板，不是 Markdown 业务规格模板。它用于指导 AI 根据 `03-原型文档.md` 生成 `docs/prototypes/html/` 下的静态 HTML 文件。

必须包含：

- HTML 文件组织方式
- 可复用组件模板来源
- 页面样式规范
- 交互模拟范围
- 静态数据约定
- 评审方式
- 不进入生产代码的声明

### 8.5 详细设计文档模板

必须包含：

- 引言
- 系统概述
- 技术架构
- 功能结构
- 模块详细设计
- 接口设计
- 数据库设计
- 安全设计
- 缓存设计
- 日志设计
- 错误码定义
- 部署与配置说明

#### 8.5.1 模块详细设计的强制要求

每个功能小节必须包含「路由与接口映射」表，列出该功能涉及的前端路由（含弹窗/抽屉触发位置）、后端接口、所需权限：

| 功能 | 前端路由 | 后端接口 | 权限编码 |
|---|---|---|---|
| 示例：OA单列表 | `/insights` | `GET /api/v1/oa-orders` | `menu:insights` |
| 示例：OA单详情 | `/insights`（抽屉） | `GET /api/v1/oa-orders/{oaNo}` | `insights:view` |

接口规范的完整定义（请求参数、响应结构、错误码）仍统一在 `6. 接口设计` 章节展开，避免在模块小节里重复。

这是开发前核心文档，质量目标参考 OmicsDB 示例 `framework/examples/OmicsDB-V1.0.0/04-详细设计文档.md`，其源文件是根目录历史文档 `V1.0.0_详细说明书.md`。

### 8.5.2 派生 API 接口文档模板（04a）

派生 API 接口文档是详细设计接口章节的人类可读独立副本，用于前后端联调、外部对接、接口走查。

必须包含：

- 输出路径：`docs/04a-API接口文档.md`
- 通用规范：请求前缀、响应结构、分页结构、时间格式、认证方式、错误码索引
- 接口分组：按业务模块组织
- 每个接口必须给出：HTTP 方法、路径、权限、请求参数表、响应字段表、请求示例、响应示例、错误码
- 来源原则：详细设计接口章节是唯一事实源；本文档不得新增、修改接口语义
- 与详细设计冲突时的处理规则：以详细设计为准并重新生成本文档
