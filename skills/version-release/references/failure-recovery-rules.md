# 失败状态与恢复规则

## 失败状态处理

| 失败场景 | 处理 |
|---|---|
| CHANGELOG 更新失败 | 不执行 Git 操作 |
| 暂存后发现 index 不符合预览清单 | 停止并只取消本次新增暂存，保留检查前已有状态 |
| commit 失败 | 保留未提交变更并报告 |
| Tag 创建失败 | 保留本地 commit 并报告 |
| 分支推送失败 | 保留本地 commit/Tag，报告目标远程分支未同步；重试前重新检查目标远程分支是否已包含该 commit，禁止盲目重复推送 |
| Tag 推送失败 | 保留本地 Tag，报告目标远程 Tag 未同步；重试前重新检查目标远程同名 Tag，只有目标远程不存在或指向同一对象时才允许继续 |
| 远程同名 Tag 在检查与推送之间出现且指向不同对象 | 停止，保留本地状态，要求人工处理 |
| 用户取消确认 | 不修改文件 |

## 显式恢复入口

仅允许通过以下入口恢复中断的推送：

```text
/version-release --resume V1.6.1 --commit <完整 commit hash>
```

## 恢复校验流程

1. 读取 `.claude/version-release/{版本号}.json`；
2. 校验以下内容完全一致：
   - commit subject（必须为 `release: 封版 {版本号}`）
   - 父提交 hash
   - 文件清单
   - CHANGELOG 最终内容
   - 本地 Tag 指向（`Tag-{版本号}` 解引用必须指向该 commit）
   - 目标 remote 和 upstream
3. 根据远程实际状态补推尚未完成的分支或 Tag；
4. 不重新创建 commit，不覆盖已有 Tag。

## 恢复的安全约束

- 任一校验不一致时停止并要求人工处理；
- 普通封版遇到已封版状态直接停止，不自动转入恢复；
- 恢复不重新生成 CHANGELOG 或 commit；
- 只有显式 `--resume` 模式允许在确认远程同名 Tag 与本地 Tag 解引用后指向同一 commit 时补推或视为已同步；
- 禁止强推、覆盖 Tag、删除分支或破坏性回滚。
