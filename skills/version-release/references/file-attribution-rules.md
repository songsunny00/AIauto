# 文件归属规则

## 默认纳入范围

- `Prds/{版本号}/**`；
- `Prds/CHANGELOG.md`；
- 当前治理仓库内 `Codes/**` 中可通过 `prd-to-code.yaml`、路径、REQ 或模块引用关联到目标版本的变更；
- 当前治理仓库内 `Tests/**` 中可通过路径、文件名、测试报告、REQ 或模块引用关联到目标版本的变更；
- 用户在预览前明确指定且可说明与本版本关联的当前仓库治理文档。

## 归属证据与优先级

文件纳入必须至少满足一项可复核证据：

1. 文件路径位于目标版本目录；
2. 文件路径、文件名或内容包含目标版本号、目标模块或已存在的 `REQ`；
3. `Codes/mappings/prd-to-code.yaml` 将文件映射到目标 `REQ`；
4. 用户在预览阶段明确指定文件并说明关联原因。

证据优先级为：版本目录/显式版本号 > REQ 映射 > 模块引用 > 用户说明。

多个证据冲突时列入待确认清单，不自动纳入。重命名和删除按 Git 的源路径与目标路径分别展示，只有两端都能建立关联时才纳入；否则暂停处理。

## 默认排除范围

- `.env`、认证态、缓存、`node_modules` 和临时测试工件；
- 无法通过上述证据建立关联的变更；
- 其他版本目录的变更。

归属不明确的文件进入待确认清单，不得猜测并自动提交。禁止使用 `git add .` 或 `git add -A`。

## 外部仓库边界

只操作当前治理仓库的工作区。若 `Codes/`、`Tests/` 是外部仓库或路径映射，不在当前 Git 工作区内，只在封版报告中列出其状态，不跨仓库提交、创建 Tag 或推送。外部仓库必须在各自仓库单独执行对应封版流程。
