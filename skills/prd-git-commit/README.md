# prd-git-commit

面向产品角色的 Git 文档提交一体化技能。通过自然语言指令完成需求文档的暂存-提交-推送，提交前对需求质量进行差异化审查，并在需求变更时自动更新变更记录、发送钉钉通知。

## 适用场景

- 产品角色不熟悉 Git 命令，希望通过自然语言完成文档提交
- 新建需求文档时需要质量审查，确保逻辑清晰、信息完整后再提交
- 需求变更时需要审查变更合理性及关联影响，确保一致性后再提交
- 需求文档（`01-需求文档.md`）变更后，需要留痕到 `05-变更记录.md`
- 需求变更需要及时通知开发和测试同事

## 前置条件

### Git 环境

- 当前目录在 Git 仓库内
- 已配置 `git config user.name` 和 `user.email`（用于提交署名和变更人记录）
- 当前用户对目标分支有推送权限

### 钉钉 Webhook 配置

在项目根目录创建 `.env` 文件（参考 `.env.example`）：

```ini
DINGTALK_WEBHOOK_URL=https://oapi.dingtalk.com/robot/send?access_token=xxxxx
DINGTALK_WEBHOOK_SECRET=SECyour_secret_here
DINGTALK_AT_MOBILES=13800138000,13900139000
DINGTALK_KEYWORD=提交需求,需求发布,需求变更
```

| 配置项                    | 必填 | 说明                                                   |
| ------------------------- | ---- | ------------------------------------------------------ |
| `DINGTALK_WEBHOOK_URL`    | 是   | 钉钉机器人 Webhook 地址                                |
| `DINGTALK_WEBHOOK_SECRET` | 否   | 加签密钥；留空或保持占位符则跳过签名                   |
| `DINGTALK_AT_MOBILES`     | 否   | 需 @ 的手机号列表，逗号分隔                            |
| `DINGTALK_KEYWORD`        | 否   | 机器人自定义关键词，逗号分隔；配置后消息自动校验并补全 |

`.env` 已在 `.gitignore` 中排除，不会被提交。

## 使用方式

直接用自然语言指令触发：

| 指令示例      | 触发行为                                  |
| ------------- | ----------------------------------------- |
| 提交需求      | 暂存-提交-推送 Prds/ 下变更               |
| 更新PRD文档   | 同上                                      |
| 提交文档修改  | 同上                                      |
| 发布需求变更  | 同上，并在 01 变更时触发变更记录+钉钉通知 |
| 同步PRD给团队 | 同上                                      |

## 执行流程

```
自然语言指令
    │
    ├─ 前置检查：Git 环境 / 工作区状态 / .env 配置（按需）
    │
    ├─ 意图解析：提取变更文件 / 变更说明 / REQ 编号 / 识别新增或变更场景
    │
    ├─ 需求审查：新增场景 → 全面质量审查 / 变更场景 → 变更点审查 + 关联影响分析
    │     │
    │     ├─ 未通过 → 输出问题清单 → 引导完善 → 重新审查
    │     └─ 通过 ↓
    │
    ├─ Git 提交：精确暂存 → Conventional Commits 提交 → 推送
    │
    └─ 涉及 01 需求变更?
          │
          ├─ 否 → 输出反馈报告
          │
          └─ 是
                ├─ 更新 05-变更记录.md（三个表格各追加一行）
                ├─ 提交并推送变更记录
                ├─ 发送钉钉通知（关键词校验 → @追加 → 签名 → 发送）
                └─ 输出综合反馈报告
```

## 需求审查机制

提交前根据变更场景执行差异化审查，审查未通过时暂停提交流程。

### 新增 01 需求审查

对需求文档整体质量进行全面审查：

| 审查维度       | 检查要点                                 |
| -------------- | ---------------------------------------- |
| 逻辑清晰度     | 前后矛盾、逻辑断层、因果倒置             |
| 表述明确性     | 模糊表述、歧义用词、未量化的验收标准     |
| 关键信息完整性 | 背景、角色、前置条件、验收条件、异常处理 |
| 功能描述一致性 | 功能点冲突、功能边界不清                 |

### 01 需求变更修改审查

除审查变更点本身外，还需进行关联影响分析：

**变更点审查：** 合理性、逻辑清晰度、必要性

**关联影响分析：**

| 检查范围     | 检查要点                   |
| ------------ | -------------------------- |
| 关联需求模块 | 其他模块是否需要同步调整   |
| 功能逻辑     | 功能依赖是否未同步更新     |
| 数据结构     | 字段/流转/状态调整是否同步 |
| 业务流程     | 上下游流程是否需要同步修改 |

### 问题清单格式

审查发现问题以表格形式反馈：

| 序号 | 问题位置 | 问题类型 | 具体表现 | 改进建议 |
| ---- | -------- | -------- | -------- | -------- |

- 问题位置精确到章节、段落或 REQ 编号
- 问题类型：逻辑不清 / 表述模糊 / 信息缺失 / 功能矛盾 / 关联未同步 / 影响未评估

## 钉钉通知机制

### 关键词校验

钉钉机器人若设置了自定义关键词（如"提交需求"），消息必须包含该关键词否则被拒绝（errcode 310000）。本技能会：

1. 从 `.env` 读取 `DINGTALK_KEYWORD`
2. 检查标题和正文是否已包含任一关键词
3. 若未包含，自动将首个关键词前缀到标题

### @ 通知

钉钉 markdown 消息要求 `@手机号` 同时出现在 `at.atMobiles` 数组和 `text` 正文末尾，否则 @ 不生效。本技能会自动将 `DINGTALK_AT_MOBILES` 中的手机号以 `@手机号` 格式追加到正文末尾。

### 通知内容

markdown 格式，包含：变更摘要、变更详情（文件/REQ/类型/变更人/时间）、相关文档链接、处理建议。

## 提交信息规范

遵循 Conventional Commits：

- 需求变更：`docs(prd): <变更摘要>`
- 变更记录：`docs(changelog): 更新 V1.6.1 变更记录 - <变更摘要>`
- 通用文档：`docs: <变更摘要>`

提交 body 包含上下文：变更文件、关联 REQ、变更类型、变更人。

## 错误处理

| 场景                    | 处理                                            |
| ----------------------- | ----------------------------------------------- |
| Git 推送失败（非快进）  | 提示先 `git pull --rebase` 再推送               |
| Git 推送失败（权限）    | 提示检查远程仓库权限或用 SSH                    |
| `05-变更记录.md` 不存在 | 询问是否新建或跳过                              |
| 钉钉 errcode 310000     | 关键词不匹配，检查 `.env` 中 `DINGTALK_KEYWORD` |
| 钉钉网络超时            | 提示网络异常，提供手动重发建议                  |
| `.env` 缺失             | 跳过钉钉通知，不阻塞 Git 提交                   |

核心原则：Git 提交是核心操作，变更记录和钉钉通知是增强操作。增强操作失败不回滚已完成的 Git 提交，但在反馈中明确报告失败项。

## 安全控制

- **禁止 `git add .` / `git add -A`**：按文件路径精确暂存，防止误提交敏感文件
- **禁止 `git push --force`**：除非用户明确要求
- **凭证保护**：Webhook URL 和 Secret 只从 `.env` 读取，禁止硬编码
- **变更记录只追加**：不修改或删除已有记录行
- **REQ 编号不自造**：必须来自需求文档已有定义

## 与其他 skill 的关系

本技能是第一批最小闭环 skills 之后的补充能力：

- `requirement-doc-bootstrap` 生成 `01-需求文档.md` 初稿
- `requirement-analysis` 解析需求抽取 REQ 清单
- **`prd-git-commit`** 负责将需求文档变更提交到 Git 并通知团队

本技能仅处理 `Prds/` 目录下的文档提交，不处理 `Codes/`、`Tests/` 目录的代码提交。
