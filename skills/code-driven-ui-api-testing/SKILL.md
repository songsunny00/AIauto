# code-driven-ui-api-testing

## 1. 目标与定位

> **定位：三种测试方案中的第 3 种。** 以「直接读取源码」为手段去**验证测试用例**，兼顾功能用例（UI 行为）与接口用例（请求/返回）。
> ① `playwright-cli-testing`——纯 UI 交互，不读代码、不调接口；② `playwright-test-implementation`——生成可长期回归的 CI 脚本；③ **本 skill（code-driven）**——读代码驱动的功能 + 接口联合验证，产出的是验证结论而非回归脚本。

提供 `01-需求文档`、`02-详细设计`，`03-测试用例` 与登录后的 `token` 后，**直接读取前端源码**，据此驱动测试：

- 从源码提取稳定定位器（`data-testid` / role / 组件结构）、校验分支与文案、状态字段值、接口契约（`baseURL` / 路径 / 入参 / 鉴权头）。
- **UI 交互验证**：用读到的稳定定位器驱动浏览器，验证页面行为与文案。
- **接口请求验证**：直接调用后端接口，验证入参校验、返回结构、错误码与业务码。
- **数据准备与接口验证合一**：当测试用例所需数据在系统中不存在时，调用接口新增数据来满足前置条件，**新增动作本身即一次接口验证**。

与 `playwright-cli-testing`（纯 UI 交互、不读代码、不调接口）和 `playwright-test-implementation`（生成 CI 回归脚本）的区别：本 skill 以**读源码**为起点、以**UI + 接口双层验证**为手段、以**接口造数即验接口**为数据策略，适合首轮专家级功能验证与接口联测，而非产出长期回归脚本。

## 2. 核心原则

- **Oracle 永远是测试用例文档，不是代码**。源码只告诉你"怎么测"（定位器、触发分支、接口契约）；"对不对"由 `03-测试用例` 的需求口径决定。FORM-003 类"代码文案≠需求文案"恰恰是应被捕获的缺陷——禁止拿代码里的字符串当预期去断言。
- **读代码不能替代运行时执行**。源码算不出 toast 是否真的弹出、网络时序、竞态。所有 UI 行为类预期必须实际驱动浏览器验证；接口类预期必须实际发请求验证。
- **数据准备与接口验证是同一动作**。调用接口新增测试数据，既铺好了 UI 用例的前置条件，也完成了对该写接口的验证（入参是否被后端接受、返回 `retCode`、错误码是否合规）。

## 3. 适用输入

- `01-需求文档.md`（必需，预期口径来源）
- `02-详细设计.md`（推荐，字段、交互、接口与校验口径）
- `03-测试用例文档.md`（必需，FT-* 功能用例来源与 Oracle）
- 前端源码仓库路径（必需，读取组件、路由、接口定义、状态字段）
- 登录后的 `token`（必需，接口鉴权；如从登录后页面开始验证，则从浏览器上下文取，不要求额外提供）
- 目标环境 `baseURL`（从源码或 `.env` 获取，禁止硬编码）

## 4. 前置检查

1. 确认前端源码已挂载/可访问；定位技术栈（Vue/React）与网络层（axios / fetch / 自封装 client）以提取接口契约。
2. 确认能拿到 `token`：优先从已登录浏览器上下文读取（cookie / localStorage / 内存态）；若用户直接提供，存入环境变量（如 `$TEST_TOKEN`），**禁止写进脚本或提交进仓库**。
3. 确认目标环境 `baseURL`；禁止硬编码，从源码配置或 `.env` 读取。
4. 统计 `03` 中的 `FT-*` 用例总数与优先级，初步分类：只读用例 / 状态切换 / 新增 / 编辑 / 删除。
5. 识别哪些用例有数据前置条件（需要特定状态、多页、空态、特殊业务数据），这些是需要"接口造数"的候选。

## 5. 工作流程

### 5.1 步骤 0：建立 Oracle

读取 `01`/`02`/`03`，把每条 `FT-*` 的预期整理成**可断言口径**：预期文案（完整原文）、预期行为、预期状态/数据变化、预期接口契约。这是后续一切判定的唯一标准。

### 5.2 步骤 1：读取前端代码，提取契约

按以下顺序读源码（只读与目标模块相关的文件，控制上下文）：

1. **路由与页面入口**：定位目标页面的组件文件与路由定义。
2. **组件模板**：提取稳定定位器（`data-testid` 优先，其次 role / 稳定属性），记录复杂组件（el-select / cascader / date-picker）的结构。
3. **校验逻辑**：提取表单校验分支与**完整校验文案**（用于 UI 文案精确比对，但预期仍以 `03` 为准）。
4. **状态字段**：提取列表/详情中状态枚举值（如 `DISABLED` / `TERMINATED` / `已停用` / `已到期`）的真实取值，避免误判。
5. **接口定义**：定位网络层封装，提取每个业务接口的 `method`、`path`、入参结构、鉴权头注入方式、`baseURL`。

### 5.3 步骤 2：梳理接口契约清单

把从源码读到的接口整理成清单（参考 `references/api-contract.md` 模板），含：接口名、method、完整 URL、必填入参、鉴权头、成功返回结构、已知错误码。该清单同时作为：

- UI 用例失败时"网络请求是否发出/返回什么"的诊断基准；
- 接口验证阶段的请求构造依据；
- 数据准备（造数）时调用哪个写接口的索引。

### 5.4 步骤 3：数据规划（探测已有 + 规划新增）

**先看后做**：先用 UI 或接口探测系统现有数据，判断用例前置条件是否满足。

- 前置条件满足 → 直接复用已有数据执行 UI 用例。
- 前置条件不满足（如缺多页数据、缺"已停用+已到期"、缺空态）→ 进入步骤 4，规划接口造数方案。

**针对场景灵活提供新增数据方案**（核心约束 2）：不同测试场景对应不同造数策略，禁止"一刀切"批量新增。决策参考：

| 测试场景 | 造数方案 | 说明 |
| --- | --- | --- |
| 分页/翻页（LIST-011） | 批量新增多条直至超过页大小 | 制造多页，触发翻页 |
| 特殊状态（已停用+已到期） | 按状态字段精确构造对应值 | 仅造满足状态组合的少数几条 |
| 空状态（DETAIL-002） | 不造数，找无消耗记录的现有数据 | 空态靠"找"而非"造" |
| 编辑/删除 | 复用本批新增的某条数据 | 见步骤 6 复用策略 |
| 校验分支（FORM-009/010/011） | 优先复用现有可编辑数据；不足时造 1 条 | 目标是触发校验，不依赖特定数据 |

### 5.5 步骤 4：数据准备与接口验证合一

当确认需要造数时，调用对应**写接口**新增数据。该调用同时完成：

1. **数据准备**：为 UI 用例铺好前置数据。
2. **接口验证**：断言该写接口的入参被后端接受、返回 `retCode === 0`、错误码在契约清单内、返回结构符合 `02` 详设。

接口调用方式（详见 `references/api-calls.md`）：

- 用 `Bash` 执行 `curl`，鉴权头从环境变量注入。真实鉴权头**必须从 axios/fetch 请求拦截器读取**（本项目 `omics-web` 为 `omics-vtk`，非 `Authorization: Bearer`）：`omics-vtk: $TEST_TOKEN`。
- 请求体按步骤 2 提取的入参结构构造，**不要凭空编造字段值**，从 `01`/`02` 与现有数据取真实枚举。
- 捕获响应体，断言 `retCode`、关键字段回显、错误码。
- 新增成功后记录该数据的**唯一标识**（ID / 编号）到测试数据清单（§7）。

**核心约束 1：单次新增数据最多 10 条。** 一次测试运行中通过接口新增的数据总量不得超过 10 条。若场景需要更多，拆分多次运行或与用户确认，禁止一次性超量造数。

### 5.6 步骤 5：UI 交互验证

用步骤 1 读到的稳定定位器驱动浏览器（参考 `playwright-cli-testing` 的交互模式与 CDP 事件规范）：

- 只读/查询/展开/状态查看类用例：验证页面渲染、文案（逐字比对，禁止关键词包含）、状态展示、数据变化。
- 写操作 UI 用例：若仅验证"数据存在时 UI 行为"，直接用步骤 4 造好的数据；若验证"通过 UI 提交→反馈链路"，则走 UI 表单提交，并捕获 toast / 弹窗 / 列表变化（FORM-004 类反馈链路必须实际跑 UI，接口造数替代不了这部分）。
- 文案类用例必须逐字比对完整预期文案；行为类用例必须验证真实行为（如翻页真的换页、缓存真的无重复请求），禁止只断言组件存在。

### 5.7 步骤 6：数据复用策略

**核心约束 3：优先复用数据。** 新增的数据必须被复用，禁止"造完即弃"：

- 新增 1 条数据后，优先把它用于后续**编辑**用例（验证字段可编辑、回显正确）。
- 编辑完成后，优先把同一条数据用于**删除**用例。
- 状态切换用例可复用该数据（禁用→启用→恢复）。
- 一条数据应串联"新增 → 编辑 → 删除"完整链路，最大化复用、最小化新增条数。

示例链路：FORM-004 接口造数 → FORM-008 编辑该数据 → FORM-016 删除该数据。

### 5.8 步骤 7：报告输出

按统一模板输出测试报告（参考 `playwright-cli-testing` 的章节结构），额外增加：

- **接口验证明细**：每条被调用的接口、入参、返回 `retCode`、断言结果、是否同时作为数据准备。
- **数据准备明细**：哪些数据通过接口新增、用于哪些用例、是否复用。
- **非通过用例**需区分根因类别：UI 行为不符 / 文案不符 / 接口返回异常 / 数据条件不足 / 前端反馈链路问题。

## 6. 接口验证规范

- 每条被调用的接口都必须有断言：至少含 `retCode === 0`（成功）或预期错误码（失败用例）、返回关键字段存在性。
- 写接口（造数）的验证与数据准备合一，不得只造数不验接口。
- 读接口的验证可结合 UI：UI 展示的值与接口返回体逐字段比对，确认前后端一致。
- 接口断言的预期口径来自 `01`/`02`/`03`，禁止照抄前端代码里的字段当预期（白盒偏见）。

## 7. 测试数据清单（实时维护）

测试过程中维护如下清单，测试报告中输出：

```markdown
| 序号 | 数据类型 | 唯一标识 | 来源接口 | 创建用例 | 复用情况 | 清理状态 | 保留原因 |
| ---- | -------- | -------- | -------- | -------- | -------- | -------- | -------- |
| 1    | 合同     | HT-T-001 | POST /contract/add | FORM-004 | 编辑(FORM-008)→删除(FORM-016) | 已删除 | — |
```

**清理状态**：已删除 / 已禁用（软清理）/ 已恢复 / 已保留。

## 8. 核心约束（硬规则）

1. **单次新增数据最多 10 条**：一次测试运行内通过接口新增的数据总量 ≤ 10 条，超出必须拆分运行或与用户确认。
2. **针对不同场景灵活提供新增数据方案**：按 §5.4 决策表为每类场景定制造数策略，禁止一刀切批量新增。
3. **优先复用数据**：新增的数据必须继续用于编辑/删除等后续用例，最大化单条数据复用，禁止造完即弃。
4. **删除安全边界**：**仅允许删除本次测试运行期间通过接口新增的数据**；绝对禁止删除、修改或影响系统中原有的存量数据。删除前必须核对测试数据清单，确认目标数据来源为本次新增；无法区分新旧时不得删除，标记"条件不满足"。
5. **作用域隔离**：禁止修改 `Tests/` 等其它测试方案的文件（测试脚本/配置/登录态）。本 skill 仅读取源码与文档、并在 `codeTests/` 目录产出验证文档，不写入或改写既有测试脚本。

## 9. 通用约束

### 作用域隔离（最高优先级）
- **禁止修改本 skill 作用域外的任何文件**，尤其禁止改动 `Tests/` 目录下已有的测试脚本与配置——那些是 `playwright-cli-testing`、`playwright-test-implementation` 等其它测试方案的产物，不属于本 skill 管辖范围。
- 本 skill 只做两件事：**读取源码/文档** 与 **产出验证文档**（报告、契约清单、数据清单、临时探针）。不得为"跑测试"而改写、新增或删除 `Tests/` 中的脚本、配置与登录态文件。

### 产出物目录
- 本 skill 产生的所有过程文档（接口契约清单、测试数据清单、验证报告、临时探针脚本/日志）统一放在仓库根的 **`codeTests/`** 目录下（不存在则新建）。
- **可复用才保留**：接口契约清单、跨用例复用的步骤模板等可沉淀为 `codeTests/` 下的长期资产。
- **临时文件任务完成后必须删除**：单次运行产生的探针脚本、curl 日志、中间草稿等，在本次验证任务结束后立即清理，不残留。
- 禁止把本 skill 的过程产物写回 `Tests/` 或其它业务/文档目录。

- 禁止把代码字符串当预期去断言（Oracle 是测试用例文档）。
- 禁止用接口造数替代"UI 提交反馈链路"的验证（FORM-004 类必须实际跑 UI）。
- 禁止把 token 写进脚本或提交进仓库，必须走环境变量。
- 禁止硬编码 `baseURL`、账号、密码，从源码配置或 `.env` 读取。
- 禁止凭空编造接口入参字段值，从 `01`/`02` 与现有数据取真实枚举。
- 禁止校验类用例只用关键词包含判断，必须逐字比对完整文案。
- 禁止把"组件存在"冒充"行为已验证"（翻页/缓存/汇总必须验真实行为）。
- 禁止删除原有数据；删除仅限本次新增数据。
- 禁止新增超过 10 条数据。
