# code-driven-ui-api-testing

## 1. 目标与定位

> **定位：三种测试方案中的第 3 种。** 以「直接读取源码」为手段去**验证测试用例**，兼顾功能用例（UI 行为）与接口用例（请求/返回）。
> ① `playwright-cli-testing`——纯 UI 交互，不读代码、不调接口；② `playwright-test-implementation`——生成可长期回归的 CI 脚本；③ **本 skill（code-driven）**——读代码驱动的功能 + 接口联合验证，产出的是验证结论而非回归脚本。

提供 `01-需求文档`、`02-详细设计`、`03-测试用例` 与登录后的 `token` 后，**直接读取前端源码**，据此驱动测试：

- **功能用例**：通过读组件模板 / i18n / 路由守卫，拿稳定定位器与真实校验口径（而非瞎猜、而非把代码当预期）。
- **接口用例**：通过读 `api/*.ts` / axios 拦截器，提取真实请求路径、鉴权头、入参结构与返回结构，直接调用接口验证，并在数据不足时造数。

## 2. 何时使用

当任务属于以下任一情景，优先调用本 skill：

- 需要**同时覆盖 UI 行为与后端接口**（例如"新增合同"既要验证弹窗交互、又要验证 add 接口）。
- **测试数据不足**：列表/表单缺少可触发边界（必填、格式、配额、启停）的数据，需要**通过接口造数**后再验证。
- 需要**从源码拿稳定定位器**（如 `data-testid`）、真实枚举值、真实校验文案（i18n key）。
- 验证**权限 / 路由守卫 / 多租户**等依赖登录态与 token 的场景。

**不使用本 skill 的情景**：纯探索式 UI 点击（用 `playwright-cli-testing`）；要产出可长期 CI 回归的脚本（用 `playwright-test-implementation`）。

## 3. 输入

| 输入 | 来源 | 说明 |
| --- | --- | --- |
| `01-需求文档.md` | `Prds/<版本>/` | 业务规则、边界条件 |
| `02-详细设计.md` | `Prds/<版本>/` | 接口/字段/状态机设计 |
| `03-测试用例.md` | `Prds/<版本>/` | **Oracle**：通过/失败的判定基准 |
| 登录 `token` | 用户侧提供，或经授权从已登录浏览器上下文读取 | 仅放环境变量，**绝不写进脚本/仓库** |
| 待测模块前端源码 | 仓库前端代码（如 `src/api/` `src/views/` `src/lang/` `src/store/`） | 本 skill 的核心"读取对象" |

## 4. 执行流程（通用，按待测模块运行时适配）

> 以下路径/字段均为**示意**；实际每一步都应以"读取当前待测模块源码"得到的真实值为准，禁止硬编码其它模块的经验值。

1. **吸收文档**：读 `01/02/03`，锁定本批用例覆盖的模块、接口与边界。
2. **读源码拿契约**（接口侧）：
   - 读 `api/<module>.ts` 抽取请求方法、路径、入参类型、返回结构；
   - 读 axios 封装 / 拦截器，确认**鉴权头字段名**（如 `omics-vtk`）与 **baseURL 前缀**（如 `/api`）；
   - 抽成「接口契约清单」(参考 `references/api-contract.md` 的形态)。
3. **读源码拿口径**（UI 侧）：
   - 读组件模板拿稳定定位器(`data-testid` 优先)、真实文案(i18n key)；
   - 读路由守卫 / store 拿权限与登录态判定逻辑。
4. **验证 token 有效**（只读调用，无写入）：用一个读接口探一下 `retCode`。
5. **判断数据是否充足**：
   - 充足 → 直接跑功能/接口验证；
   - 不足 → 进入造数（步骤 6）。
6. **造数 + 接口验证合一**（写接口）：
   - 先调用**选项/枚举接口**取真实 `instCode`/`productNo`/`projectCode` 等（禁止编造）；
   - 调新增接口造数，`retCode===0` 即"造数成功 + 写接口验证通过"；把返回主键记到**测试数据清单**；
   - **复用同一条**：编辑/启停验证复用步骤 6 造出的数据，不重复造数。
7. **功能验证**：基于步骤 3 的稳定定位器与真实文案，结合 UI 交互断言预期（Oracle 仍是 `03-测试用例`）。
8. **软清理**：优先"禁用/启停"软清理；无删除接口则保留（≤5 条）；**仅当确有删除接口且能区分新旧时，才删本次新增数据**。

## 5. 接口调用写法（Windows/PowerShell 已实测要点）

> 完整可抄模板见 `references/api-calls.md`（注：该文件是某模块的示例产物，非通用模板）。

- **PowerShell 下不要用 `curl -d '{...}'`**：会把 JSON 双引号吞掉导致后端 JSON 解析报错。改用 `Invoke-RestMethod` + `ConvertTo-Json -Compress`，可靠免引号烦恼。
- token 只放环境变量：`$env:TEST_TOKEN = "<token>"`，请求头引用它；**绝不把 token 写进脚本或仓库**。
- 统一响应结构通常为 `{ retCode, retInfo, result }`，`retCode==='0'` 即成功；`retCode` 非 0（如 `201`）常表示 token 失效——需重新取 token。

## 6. 复用 assets / references（按需，非照搬）

本 skill 自带 `references/`，里面的文件是**过去实测任务的产物示例**（如 billingConfig 模块），用于展示"接口契约清单 / 调用模板"的产出形态，**不是所有模块的通用药方**：

- 启动新模块验证时，**不要直接套用**这些示例的字段与路径；应重新读取待测模块源码生成当次产物。
- 若某模块的契约/调用模板具备长期复用价值，把重新生成的版本沉淀到 **`codeTests/`** 目录（见 §9），而非改回 `references/`。

## 7. 硬规则（不可妥协）

1. **Oracle 是测试用例文档**：判定通过/失败的唯一标准是 `03-测试用例`，不是前端代码里的字符串。代码文案与用例一致即 PASS，不一致即缺陷（先核对是否报告转述差异）。
2. **读源码拿稳定定位器**：UI 定位优先 `data-testid`；文案断言用 i18n key 的真实值；不硬编码会随语言变化的 placeholder。
3. **枚举真实化**：造数的外键枚举(instCode/productNo/…)必须从"选项接口"取真实值，禁止编造。
4. **复用造数**：编辑/启停验证复用同一条新增数据，不重复造数；单次运行新增 ≤ 10 条。
5. **作用域隔离**：禁止修改 `Tests/` 等其它测试方案的文件（测试脚本/配置/登录态）。本 skill 仅读取源码与文档、并在 `codeTests/` 目录产出验证文档，不写入或改写既有测试脚本。
6. **删除安全边界**：**仅允许删除本次测试运行期间通过接口新增的数据**；绝对禁止删除、修改或影响系统中原有的存量数据。删除前必须核对测试数据清单，确认目标数据来源为本次新增；无法区分新旧时不得删除，标记"条件不满足"。

## 8. 通用约束

### 作用域隔离（最高优先级）
- **禁止修改本 skill 作用域外的任何文件**，尤其禁止改动 `Tests/` 目录下已有的测试脚本与配置——那些是 `playwright-cli-testing`、`playwright-test-implementation` 等其它测试方案的产物，不属于本 skill 管辖范围。
- 本 skill 只做两件事：**读取源码/文档** 与 **产出验证文档**（报告、契约清单、数据清单、临时探针）。不得为"跑测试"而改写、新增或删除 `Tests/` 中的脚本、配置与登录态文件。

### 产出物目录
- 本 skill 产生的所有过程文档（接口契约清单、测试数据清单、验证报告、临时探针脚本/日志）统一放在仓库根的 **`codeTests/`** 目录下（不存在则新建）。
- **可复用才保留**：接口契约清单、跨用例复用的步骤模板等可沉淀为 `codeTests/` 下的长期资产。
- **临时文件任务完成后必须删除**：单次运行产生的探针脚本、curl 日志、中间草稿等，在本次验证任务结束后立即清理，不残留。
- 禁止把本 skill 的过程产物写回 `Tests/` 或其它业务/文档目录。

## 9. 产出物

统一落在 **`codeTests/`**（仓库根，不存在则新建）：

- **验证报告**（必出，可复用）：含用例结论、接口验证明细(retCode/字段/错误码)、数据准备明细(造了什么/主键/如何清理)、缺陷清单。
- **接口契约清单**（按需，可复用）：从源码提取的请求路径/鉴权头/入参/返回结构。
- **测试数据清单**（按需，可复用）：本次造数的主键、来源标记(本次新增)、清理方式。
- **临时探针/日志**（一次性，任务完成即删）。
