# testcase-generation

## 1. 目标

把 `01-需求文档.md` 与 `02-详细设计文档.md` 转成 `03-测试用例文档.md` 所需的最小结构与测试点清单。

## 2. 适用输入

- `01-需求文档.md`
- `02-详细设计文档.md`
- `01c-原型文档.md`（如有）
- 模块 `TRACE.yaml`

## 3. 期望输出

至少输出：

1. `03-测试用例文档.md` 章节建议
2. `FT-*` 测试点清单
3. `IT-*` 测试点清单
4. 每个测试点对应的 `REQ`
5. UI 自动化 / API 自动化 / 手工测试建议归属
6. P0 / P1 场景建议

## 4. 使用步骤

1. 读取并整理 `REQ` 与验收点。
2. 将用户路径类场景拆成 `FT-*`。
3. 将接口规则、边界、权限、状态流场景拆成 `IT-*`。
4. 给每个测试点标记建议覆盖方式：手工 / UI / API。
5. 输出可直接落入 `03-测试用例文档.md` 的结构化内容。

## 5. 输出格式建议

```markdown
## 03 文档建议结构
- 

## FT 清单
- FT-... -> REQ-... -> {场景}

## IT 清单
- IT-... -> REQ-... -> {场景}

## 覆盖建议
- UI 自动化：
- API 自动化：
- 手工保留：
```

## 6. 约束

- `FT/IT` 必须沿用对应 `REQ` 的路径编码。
- 不单独维护额外映射文件，直接保持 `REQ -> FT/IT` 主线。
- 要显式区分哪些场景适合 UI 自动化、哪些适合 API 自动化。
- 若 P0 / P1 需求点没有对应测试点，要明确指出。
