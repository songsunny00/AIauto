# Prds 目录说明

## 1. 定位

`Prds/` 是单个系统项目的需求资产根目录，用于沉淀：

- 主需求文档
- 增量需求文档
- 数据流转设计
- 原型说明文档
- 详细设计文档
- 测试用例文档
- 版本级测试执行记录与变更记录

## 2. 目标目录模型

推荐按"系统级版本资产上收、稳定基线文档下沉"的方式组织：

```text
Prds/
├─ README.md
├─ CHANGELOG.md
├─ Vx.y.z/
│  ├─ 01a-增量需求文档.md
│  ├─ 04-测试执行记录.md
│  └─ 05-变更记录.md
└─ 模块叶子目录/
   ├─ INDEX.md
   ├─ TRACE.yaml
   ├─ 01-需求文档.md
   ├─ 01b-数据流转设计.md
   ├─ 01c-原型文档.md
   ├─ 02-详细设计文档.md
   └─ 03-测试用例文档.md
```

## 3. 查找建议

### 3.1 查某个功能点的主基线

去对应模块叶子目录查：

- `01-需求文档.md`
- `02-详细设计文档.md`
- `03-测试用例文档.md`
- `TRACE.yaml`
- `INDEX.md`

### 3.2 查某个版本本轮变化

去对应版本目录查：

- `01a-增量需求文档.md`
- `04-测试执行记录.md`
- `05-变更记录.md`

## 4. 当前说明

- 当前仓库中仍保留部分较早期、较平铺的需求示例文件。
- 这些示例可以继续作为历史参考，但新落地资产应优先遵循当前蓝图目录模型。
- 本批次不对旧示例做强制迁移，以避免把"方法落地"和"历史目录整理"混成一件事。

## 5. 版本归档

版本测试结束后，由版本负责人 / PM 角色执行版本归档操作，将版本目录下的正式交付物（01/02/03）回写为模块基线全量文档。

- **触发方式**：通过 `version-archive` skill 执行（如"归档 V1.6.1"）
- **归档模式**：首次沉淀（模块基线目录无文件时全量覆盖）或增量合并（已有基线时按 REQ 区块合并）
- **归档产出**：模块基线目录下的 01/02/03 + INDEX.md，以及 CHANGELOG.md 回写状态更新
- **设计规范**：详见 `docs/superpowers/specs/2026-08-13-version-archive-design.md`
