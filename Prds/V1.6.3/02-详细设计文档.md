###### 4. 处理逻辑

**主表加载与渲染**：

1. 页面初始化 / 查询触发后，调用 `POST /base/quota/tenant/page` 获取租户聚合分页结果 ↓
2. 适配层将 `QuotaTenantVO[]` 转换为主表行模型，渲染主表 8 个字段：

   - 文件下载次数（`downloadLimitMax`，当前生效合同 MAX）
   - 合同数量（`contractCount`，所有有效合同数；hover 展示 `contracts[]` 明细）
   - 授权状态（`authStatus`，`ENABLED`/`DISABLED`）

**展开子表**：

5. 用户点击某行展开按钮 ↓

7. 调用 `POST /base/quota/contract/page`，入参带 `instCode` 筛选该租户所有有效合同（含过期、即将生效）`[DESIGN-SUPPLEMENT]` ↓

**已知约束**：

- 主表「分析产品套餐编码」「检测项目」「样本分析总次数」「文件下载次数」均基于「当前生效合同」聚合；五态计数与 hover 明细覆盖「所有有效合同」。
- 禁用机构授权后，子表中各合同的合同状态保持原值不变（不统一变为「已停用」），仅冻结该机构下所有合同的样本提交与配额消耗能力；重新启用后立即恢复可用。
- 机构授权启停与机构启停（`base_auth_institution.status`）独立，互不联动；无授权记录的租户默认 `ENABLED`，首次禁用才落库。
- 子表「增值存储已用容量」本期因后端 `storageUsedTb` 恒为 null，该列本期无可用值，展示「—」或留空 `[DESIGN-SUPPLEMENT]`。
- 主表「合同数量」hover 最多展示前 7 条，超出加滚动条，按合同到期时间倒序排列。
- 过期、停用、终止的合同不纳入主表汇总字段计算，但在子表中展示。

###### 4. 处理逻辑

1. 用户点击「明细」 ↓
2. 抽屉打开，重置分页状态与详情对象，入参为 `instCode` ↓
3. 并发请求：
   - `POST /base/quota/tenant/summary`（顶部汇总区）
   - `POST /base/quota/usage/detail`（分析用量，按 `instCode` 查询）`[DESIGN-SUPPLEMENT]`
   - `POST /base/quota/usage/history`（历史变更，按 `instCode` 查询；返回含 `changeType`/`changeTypeDesc`）`[DESIGN-SUPPLEMENT]`
   - `POST /base/quota/usage/storage/page`（存储用量，按 `instCode` 查询，按 `backupTime` 倒序，排除 `FAILED` 状态）
   - `POST /base/quota/usage/download/page`（下载记录，按 `instCode + module + fileId` 聚合，排除 `FAILED` 状态） ↓
4. 顶部汇总区分块渲染（顶部概览信息行 + 分析资源、下载策略、存储资源三个区块，以卡片形式独立展示） ↓
5. 分析用量表展示任务级数据；存储用量表（仅购买增值存储的租户展示）展示备份文件记录；下载记录表展示全量下载记录；历史变更表展示操作日志摘要 ↓
6. 用户切换各表分页时，仅刷新对应数据域 ↓
7. 点击「关闭」按钮后关闭抽屉

###### 6. 输出结果

**顶部汇总区输出**：

- 顶部概览信息行：机构名称（`instName`）、授权状态（`authStatus`）、有效合同数量（前端按 `contracts[]` 中 `displayStatus ∈ {NORMAL, EXPIRING_SOON}` 计数，或后端返回字段）
- 分析资源区块：总次数（`totalQuota`，生效合同所有套餐模块 Σ `sample_quota`）、累计消耗（`usedCount`，Σ(`used_count`+`frozen_count`)，**含预扣冻结**）、当前剩余（`remainCount` = `totalQuota` − `usedCount`）
- 下载策略区块：文件下载次数（`downloadLimit`，生效合同 MAX，默认 2）
- 存储资源区块：序号（前端按顺序生成）、合同编号、免费存储期限（`storageDays`，生效合同 MAX）、增值存储总容量（`storageCapacityTb`，仅 `storage_enabled=1` 的生效合同 MAX；未开通为 null）、增值存储已使用（对接文档 §3.3 `storageUsedTb` 本期恒为 null，前端不要依赖，展示「—」 `[DESIGN-SUPPLEMENT]`）、存储服务生效时间（取最早）、增值存储到期时间（`storageEndDate`，仅开通存储的生效合同 MAX；取最晚）

> 注意 §4.1.4.1 租户 page 与 §4.1.4.5 租户 summary 的口径差异：page 的 `contractCount` 统计「所有有效合同」，summary 的 `contractCount` 统计「当前生效合同」；page 的 `usedCount` 口径若为「仅已确认」则与 summary 的「含预扣冻结」口径不同。前端在两处展示时需按各自口径渲染。

**分析用量表输出**（按消耗时间由近到远排序）：

- UI 结果：序号、芯片 ID / RUN ID、任务编号、合同编号、分析产品套餐编码、检测项目、产品套餐、分析结束时间、分析状态、消耗次数。
- 返回数据：序号（`usageList[].seq`，前端生成）、芯片/Run ID（`usageList[].chipId`、`usageList[].runId`）、任务编号（`usageList[].taskName`）、合同编号（`usageList[].contractNo`）、分析产品套餐编码（`usageList[].analysisPackageCode`）、检测项目（`usageList[].projectCode`）、产品套餐（展示 `usageList[].productNo`，按「编号 名称」展示，名称缺失时仅展示编号）、分析结束时间（`usageList[].opTime`，精确到秒）、分析状态（分析成功/分析失败）、消耗次数（分析成功为正数，分析失败为负）。

**存储用量表输出**（仅购买增值存储的租户展示，按 `backupTime` 倒序，排除 `FAILED` 状态）：

- UI 结果：序号、文件名称、文件大小、备份时间、合同编号、存储服务到期时间。
- 返回数据：序号（前端生成）、文件名称（`fileName`）、文件大小（`fileSizeBytes`，字节数；前端按值动态显示 GB/TB：≥1TB 显示 TB，否则显示 GB，保留 2 位小数）、备份时间（`backupTime`，精确到秒）、合同编号（`contractNo`）、存储服务到期时间（`storageEndDate`，从合同维度带入）。

**下载记录表输出**（按 `instCode + module + fileId` 聚合为文件级记录，排除 `FAILED` 状态）：

- UI 结果：序号、文件名称、文件大小、文件创建时间、下载次数/上限、下载方式（浏览器/COEUS）、最近下载时间、操作人。
- 返回数据：序号（前端生成）、文件名称（`fileName`）、文件大小（`fileSizeBytes`，字节数；前端按值动态显示 GB/TB：≥1TB 显示 TB，否则显示 GB，保留 2 位小数）、文件创建时间（`fileCreateTime`，精确到秒）、下载次数/上限（`usedCount`/`downloadLimit`）、下载方式（`downloader`：`BROWSER`/`CLIENT`，前端映射为浏览器/COEUS）、最近下载时间（`lastDownloadTime`，精确到秒）、操作人（`lastOperatorName`）。

**历史变更表输出**（按消耗时间由近到远排序，聚合所有合同全量变更记录）：

- UI 结果：序号、变更时间、合同编号、变更类型、变更内容、操作人。
- 返回数据：序号（`historyList[].seq`，前端生成）、变更时间（`historyList[].createTime`，后端字段 `createTime`）、合同编号（`historyList[].contractNo`）、变更类型（`historyList[].changeType`：`QUOTA_ADJUST`/`STORAGE_ADJUST`/`DOWNLOAD_ADJUST`，可能为 null（历史数据）；`changeTypeDesc` 中文描述）、变更内容（`snapshotBefore`/`snapshotAfter` JSON 文本 diff，字段名：原始值 → 变更值，多个字段用分号隔开；本期起快照含增值存储字段 `storageEnabled`/`storageCapacityTb`/`storageStartDate`/`storageEndDate`，前端 diff 渲染需兼容新 key）、操作人（`historyList[].createUserName`，后端字段 `createUserName`）。

**已知约束**：

- 抽屉按租户维度聚合展示，`open` 入参为 `instCode`；底部仅保留「关闭」按钮。
- 顶部汇总区采用分块展示布局（顶部概览信息行 + 分析资源、下载策略、存储资源三个区块，以卡片形式独立展示），常驻置顶。

- 存储用量模块仅购买增值存储的租户展示（机构下存在增值存储合同即展示）。
- 分析用量「消耗次数」分析成功为正数，分析失败为负。
- 历史变更「变更类型」本期起新增 `changeType`（`QUOTA_ADJUST`/`STORAGE_ADJUST`/`DOWNLOAD_ADJUST`）与 `changeTypeDesc`，历史数据无此列为 null。

- 明细抽屉为只读查看场景，不支持在当前视图内直接编辑配置。
- 「增值存储已使用」本期因后端 `storageUsedTb` 恒为 null，前端不要依赖该字段，展示「—」。

**接口契约补充说明 `[DESIGN-SUPPLEMENT]`**：

- 分析用量、历史变更：V1.6.1 基线按 `contractId` 查询，V1.6.3 改为租户维度，推断入参由 `contractId` 改为 `instCode`（或新增租户级用量接口）。对接文档未明确租户级用量接口契约，**待后端补充确认**。

## 6. 开发落地约束与对应关系

### 6.1 前端实现约束

1. **局部状态优先**：沿用 V1.6.1，本模块所有页面状态均由组合式 API 管理，不新增 Pinia store。
2. **适配层统一收口**：V1.6.3 租户聚合视图与合同视图的双口径在 `billingConfig.ts` 收口；参数标准化、接口返回结构映射、历史 JSON 解析（含新增 `changeType`）、汇总字段生成都放在适配层，组件层不重复做协议转换。
3. **双口径注意**：租户 `page` 与租户 `summary` 的 `contractCount` / `usedCount` 口径不同（page=所有有效合同 / summary=当前生效合同；usedCount 是否含预扣冻结不同），前端在主表与抽屉两处分别按各自口径渲染，不可混用。
4. **只读门禁同时保留前后端双重校验**：V1.6.3 编辑弹窗的可编辑性按检测项目类型区分（SD5193 按合同状态/已用容量，非 SD5193 按分析次数消耗），前端做只读控制，后端仍做最终校验。
5. **存储配置约束**：存储开关一次性配置（开通后不可关闭）、起止时间不可修改、容量可调整；前端编辑表单需禁用相应控件。
6. **服务权益联动显隐**：服务权益区按是否选非 SD5193 套餐联动显隐；只勾 SD5193 时合同生效/到期时间取存储时间且不可编辑。
7. **页面入口按菜单挂载**：不拆出新增页或详情页，全部在页面内部完成。
