# 配置中心-商业化计费配置详细设计文档

## 1. 引言

### 1.1 编写目的

本文档只说明“商业化计费配置”模块落地所需的页面结构、接口映射、状态边界和关键实现约束，作为开发、联调、测试的直接依据；需求背景和业务目标以 `01-需求文档.md` 为准。

## 2. 技术架构

### 2.1 模块架构概述

本模块沿用系统既有前后端分离模式，不单独引入新的框架或插件库。模块内部由页面容器、展开明细、新增/编辑弹窗、明细抽屉和接口适配层组成，共同承接合同查询、配置维护、状态切换和明细查看；全局技术栈与基础设施说明统一放在 `00-全局说明` 中维护。

### 2.2 实现结构与关键约束

| 结构单元      | 实现入口                                                     | 主要职责                                                                 | 对应接口                                                                                                                                                                                          | 关键约束                                                                                                                   |
| ------------- | ------------------------------------------------------------ | ------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------- |

1. 页面 `onMounted`
   ↓
2. 并发加载查询区选项：机构、检测项目、产品套餐
   ↓
3. 调用 `baseTableRef.onSearch()`
   ↓
4. `getBillingListApi` 将多选数组参数规范化为请求体字段

5. 调用 `POST /base/quota/contract/page`
   ↓
6. 接口适配层把 `ContractRecordResponse[]` 转换为 `BillingRecord[]`

7. 页面渲染主表

- UI 结果：刷新主表与分页；保留当前查询条件。
- 返回数据：主表使用 `BillingRecord[]` 渲染，核心字段包括：机构名称（`orgName`）、检测项目（`projectCodes`，展示时去重拼接）、样本分析总次数（`totalQuota`）、数据存储期限（天）（`storageDays`）、单样本下载次数（`downloadTimes`）、合同编号（`contractNo`）、合同周期（`contractStart`、`contractEnd`）、合同状态（`displayStatus`）；操作列基于 `id`、`enabled`、`hasConsumed`、`status` 提供编辑、明细、启用/禁用入口，序号由前端分页序号生成。

###### 7. 异常处理与已知约束

| 异常场景             | 触发条件                             | 处理方式                           | 用户提示                              | 是否可重试 |
| -------------------- | ------------------------------------ | ---------------------------------- | ------------------------------------- | ---------- |
| 查询区选项加载失败   | 机构/项目/产品接口异常               | 页面停止初始化 loading，保留空选项 | 待需求/后端补充文案                   | ✅         |
| 合同分页查询失败     | `/base/quota/contract/page` 返回异常 | 保留当前筛选条件与页码，不清空输入 | 待需求/后端补充文案                   | ✅         |
| 合法状态值之外的筛选 | 前端传入非法 `displayStatus`         | 由后端返回业务错误码               | 合同展示状态不合法: `<displayStatus>` | ✅         |

###### 2. 呈现形式与前端入口

| 项            | 内容                        |
| ------------- | --------------------------- |
| 呈现形式      | 主表状态标签 + 二次确认按钮 |
| 实现入口      | `index.vue`                 |
| 打开方式      | 点击“启用”或“禁用”          |
| 返回/关闭行为 | 确认框关闭后返回当前列表    |

###### 3. 输入参数

| 原字段名 | 参数名       | 类型     | 必填  | 默认值 | 校验规则                       | 说明         | 示例         |
| -------- | ------------ | -------- | ----- | ------ | ------------------------------ | ------------ | ------------ |

| 目标状态 | `status`     | `string` | ✅ 是 | -      | 仅允许 `ENABLED` 或 `DISABLED` | 启停目标状态 | `DISABLED`   |

###### 4. 处理逻辑

1. 主表根据 `displayStatus` 渲染状态标签
   ↓
2. 若 `row.enabled = true`，展示“禁用”；否则展示“启用”
   ↓
3. 用户点击按钮，弹出二次确认框
   ├─ 点击取消：终止流程
   └─ 点击确认：进入步骤 4
   ↓
4. 调用 `POST /base/quota/contract/toggle/{contractId}/{status}`
   ↓
5. 成功后提示启用/禁用成功
   ↓

   ↓
5. 用量明细表展示任务级数据；历史变更表展示操作日志摘要
   ↓
6. 用户切换用量或历史分页时，仅刷新对应数据域
   ↓
7. 点击“关闭”按钮后关闭抽屉

## 6. 开发落地约束与对应关系

### 6.1 前端实现约束

1. **局部状态优先**：本模块所有页面状态均由组合式 API 管理，不新增 Pinia store。
2. **适配层统一收口**：参数标准化、接口返回结构映射、历史 JSON 解析、汇总字段生成都放在 `billingConfig.ts`，组件层不重复做协议转换。
3. **只读门禁同时保留前后端双重校验**：前端依据 `hasConsumed` 做只读控制，后端仍需依据 `usedCount` 做最终编辑校验。
4. **汇总区计算口径固定**：`summary.totalQuota` 取合同级 `sampleTotalQuota`；`summary.totalUsed` 取用量明细列表 `usedCount` 合计；`summary.totalRemain = summary.totalQuota - summary.totalUsed`。不能直接累加任务级列表里的 `sampleQuota / remainCount`，否则会因产品套餐级额度重复展示而重复计数。
5. **页面入口按菜单挂载，不依赖独立路由跳转**：本次设计不拆出新增页或详情页，全部在页面内部完成。
