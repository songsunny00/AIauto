# 全局公共说明（项目系统级公共规范基线）

## 0. 使用说明

- **定位**：本文件是**一个项目系统**内的通用公共规范基线，定义该系统跨所有模块通用的角色权限体系、全局规则和非功能基线。同一项目下的多个 feature 级 `01-需求文档.md` 共享本基线，不重复定义。
- **上游输入**：项目系统架构设计、公司技术规范、业务方确认的系统级约定。
- **下游消费者**：
  - `docs/01-需求文档.md`（各模块需求文档引用本基线，只写本模块特有内容）
  - `docs/04-详细设计文档.md`（引用角色编码、数据格式、鉴权方式等）
  - `docs/04b-后台文档.md`、`docs/04c-前端文档.md`、`docs/05-测试用例文档.md`
- **覆盖规则**：每个小节标注基线类型：
  - **不可覆盖**：所有模块必须遵守，不允许特例。
  - **项目可覆盖**：模块级 01 文档可在本基线之上声明覆盖项，覆盖项必须显式标注「覆盖全局基线」并说明原因。
- **维护原则**：本文件由项目架构组统一维护，变更需评审并同步通知所有模块负责人。基线变更时，所有引用本文件的 01/04 文档须检查是否受影响。
- **命名约定**：输出到 `docs/00-全局公共说明.md`；文档正文中文，代码标识/接口字段/数据库字段/角色编码/权限编码使用英文。

## 1. 角色与权限定义

> **填写指引**：定义本项目系统的角色编码体系、权限编码规范和数据权限通用规则。角色编码与权限编码一经定义，不允许在下游文档变形。各模块 01 文档的第 3 章只写本模块特有的角色与权限，公共部分引用本章。

### 1.1 角色编码规范（不可覆盖）

> **填写指引**：规定本项目角色编码的命名规则，确保全系统统一。

| 项 | 规则 | 示例 |
|---|---|---|
| 命名风格 | 全大写英文，单词间用下划线分隔 | `ADMIN` / `DATA_MANAGER` |
| 长度限制 | 2-30 字符 | - |
| 编码稳定性 | 编码一经创建不得复用、不得改名（角色废弃时保留编码） | - |
| 存储字段 | 数据库字段 `role_code`，接口字段 `roleCode` | - |

> **常见错误**：
> - 角色编码大小写不一致（`Admin`/`ADMIN` 混用）。
> - 角色废弃后编码被新角色复用，导致历史数据权限错乱。

### 1.2 通用角色清单（项目可覆盖）

> **填写指引**：列出本项目系统的基础角色体系。各模块若需要模块特有角色，在模块 01 文档第 3 章补充；若直接使用以下角色，填"同全局基线"即可。

| 角色编码 | 角色名称 | 角色描述 | 上级角色 | 备注 |
|---|---|---|---|---|
| `ADMIN` | 系统管理员 | 拥有全部权限，可管理所有用户和配置 | - | 不可覆盖 |
| `{ROLE_CODE}` | {角色名称} | {职责描述} | {上级角色} | - |

### 1.3 权限编码规范（不可覆盖）

> **填写指引**：规定本项目权限编码的命名规则。

| 项 | 规则 | 示例 |
|---|---|---|
| 命名格式 | `module:action` | `system:user:add` / `insights:view` |
| module | 小写英文，对应模块编码 | `system` / `insights` / `config` |
| action | 小写英文动词 | `view` / `add` / `edit` / `delete` / `export` |
| 菜单权限 | `menu:{module}` | `menu:insights` |
| 特殊权限 | `公开`（无需登录）/ `已登录`（仅需登录） | - |
| 存储字段 | 数据库字段 `permission_code`，接口字段 `permissions[]` | - |

> **常见错误**：
> - 权限编码命名风格不统一（`menu:insights` 与 `menuInsights` 混用）。
> - 把菜单权限和操作权限混在一起，命名无法区分。

### 1.4 通用权限清单（项目可覆盖）

> **填写指引**：列出跨模块通用的权限编码。模块特有权限在各模块 01 文档第 3 章补充。

| 权限编码 | 权限名称 | 适用角色 |
|---|---|---|
| `menu:{module}` | {模块}菜单访问 | [{角色列表}] |
| `{module}:view` | {模块}查看 | [{角色列表}] |

### 1.5 数据权限通用规则（项目可覆盖）

> **填写指引**：定义全系统通用的数据可见性规则。模块特有数据权限规则在各模块 01 文档补充。

| 规则名 | 规则内容 | 实现方式 |
|---|---|---|
| 管理员全量可见 | `ADMIN` 角色可查看全量数据 | 后端权限中间件注入 |
| 本机构数据隔离 | 非 `ADMIN` 角色只能查看所属机构数据 | 后端注入机构过滤条件 |
| {规则名} | {规则内容} | {实现方式} |

## 2. 全局规则

> **填写指引**：定义全系统通用的技术规则。各模块 01 文档的第 7 章只写本模块特有规则或对全局规则的覆盖项。

### 2.1 数据格式（不可覆盖）

| 数据类型 | 格式规则 | 示例 |
|---|---|---|
| 日期 | `yyyy-MM-dd` | `2026-05-18` |
| 时间 | `yyyy-MM-dd HH:mm:ss` | `2026-05-18 10:00:00` |
| 时间戳 | ISO 8601，含时区 | `2026-05-18T10:00:00+08:00` |
| 金额 | 分为单位存储，元为单位展示（2 位小数） | 存储 `10050`，展示 `100.50` |
| 布尔值 | 数据库 `0`/`1`，接口 `true`/`false` | - |
| 枚举值 | 数据库存数字编码，接口返回字符串编码 | DB `1`，API `"ENABLED"` |
| ID | 雪花 ID 或 UUID，字符串传输 | `"2060597387326226432"` |

### 2.2 鉴权方式（不可覆盖）

| 项 | 规则 | 说明 |
|---|---|---|
| 认证方式 | JWT | 前后端分离项目统一 |
| Token 传递 | Header `Authorization: Bearer <token>` | - |
| Token 有效期 | {N} 小时 | 超时后前端刷新或跳转登录 |
| 刷新机制 | {有/无 refreshToken} | - |
| 登出 | 前端清除 Token，后端可选加入黑名单 | - |

### 2.3 密码规则（不可覆盖）

| 项 | 规则 | 示例 |
|---|---|---|
| 长度 | 8-32 字符 | - |
| 字符集 | 至少包含大写字母、小写字母、数字、特殊字符中的 3 种 | `Abc@1234` |
| 加密存储 | BCrypt（cost ≥ 10） | - |
| 密码过期 | {N} 天强制修改 / 不过期 | - |
| 历史密码 | 新密码不能与最近 {N} 次相同 | - |

### 2.4 分页约定（不可覆盖）

| 项 | 规则 | 示例 |
|---|---|---|
| 页码参数 | `page`（从 1 起） | `page=1` |
| 每页条数 | `pageSize`（默认 20） | `pageSize=20` |
| 最大条数 | `pageSize` ≤ 100 | 防止全量拉取 |
| 响应结构 | `{ "list": [], "total": N, "page": N, "pageSize": N }` | - |
| 排序参数 | `sortField` + `sortOrder`（`asc`/`desc`） | `sortField=createTime&sortOrder=desc` |

### 2.5 时区与语言（不可覆盖）

| 项 | 规则 | 说明 |
|---|---|---|
| 时区 | `Asia/Shanghai`（UTC+8） | 前后端统一 |
| 语言 | 中文（zh-CN） | - |
| 国际化 | 前端使用 i18n，不在组件内写死中文业务文案 | 按钮文案、枚举翻译走字典 |

## 3. 非功能需求基线

> **填写指引**：定义全系统通用的非功能指标基线。各模块 01 文档的第 8 章只写本模块覆盖项或补充指标。标"不可覆盖"的安全基线所有模块必须遵守。

### 3.1 性能基线（项目可覆盖）

| 指标 | 基线值 | 说明 |
|---|---|---|
| 列表接口 P95 响应 | ≤ 800ms | 主要列表查询接口 |
| 详情接口 P95 响应 | ≤ 500ms | 单条详情查询 |
| 保存接口 P95 响应 | ≤ 1000ms | 新增/编辑保存 |
| 页面首屏渲染 | ≤ 2s | 含接口请求 |

> **模块覆盖方式**：若某模块接口性能要求不同（如导出接口允许更长耗时），在模块 01 第 8 章声明覆盖项。

### 3.2 并发基线（项目可覆盖）

| 指标 | 基线值 | 说明 |
|---|---|---|
| 系统峰值 QPS | {N} | 全系统峰值 |
| 单接口峰值 QPS | {N} | 热点接口 |
| 并发用户数 | {N} | 同时在线 |

### 3.3 安全基线（不可覆盖）

| 指标 | 规则 | 说明 |
|---|---|---|
| 数据传输 | HTTPS | 全站强制 |
| 敏感字段脱敏 | 手机号/身份证/邮箱在展示时脱敏 | `138****8888` |
| SQL 注入防护 | 参数化查询，禁止拼接 SQL | - |
| XSS 防护 | 前端输出转义，后端输入过滤 | - |
| CSRF 防护 | Token 校验 | - |
| 操作审计 | 关键操作（增删改）记录审计日志 | 含操作人/时间/内容 |
| 越权防护 | 每个接口校验当前用户对该资源的权限 | 防水平/垂直越权 |

### 3.4 可用性基线（项目可覆盖）

| 指标 | 基线值 | 说明 |
|---|---|---|
| 月可用性 | ≥ 99.5% | - |
| 计划停机 | 提前 24h 通知 | - |
| 数据备份 | 每日全量 + 实时增量 | 保留 {N} 天 |
| 故障恢复 | RTO ≤ {N}h，RPO ≤ {N}min | - |
